## 1. 이 작업의 목적

Phase 0에서 Claude가 작성한 문서 기반을 **Codex가 독립적으로 검토**합니다.

> **핵심 전제:** Codex는 Claude의 대화 기록을 볼 수 없습니다. 그것이 의도입니다.
> **저장소 파일만 보고** 판단하십시오. 파일에 없는 내용을 Claude에게 물어볼 수 없습니다.
> 파일만 보고 이해되지 않는다면, **그것 자체가 발견해야 할 결함**입니다.

이 작업은 "잘 썼는지 칭찬하기"가 아닙니다. **틀린 곳과 빠진 곳을 찾는 것**입니다.
문제를 못 찾았다면 충분히 읽지 않은 것일 가능성이 높습니다.

## 6. 작업 절차

**먼저 확인:** Phase 0 문서 기반이 `main`에 병합되었는가?

```bash
git fetch origin
git ls-tree --name-only origin/main    # AGENTS.md 등이 보이면 병합된 것
```

**경우 A — 이미 `main`에 병합된 경우**

```bash
git switch -c codex/task-001-repo-review origin/main
```

**경우 B — 아직 PR 상태인 경우 (Phase 0 시점의 기본 상황)**

리뷰 대상은 Claude의 PR 브랜치입니다. 그 브랜치에서 분기하십시오.
`main`에서 분기하면 리뷰할 문서 자체가 없습니다.

```bash
git fetch origin claude/media-clarity-foundation-4fveu9
git switch -c codex/task-001-repo-review origin/claude/media-clarity-foundation-4fveu9
```

> 경우 B에서도 **Claude의 브랜치에 직접 커밋하지 않습니다** (`AGENTS.md` §3).
> 분기해서 만든 자기 브랜치에만 커밋합니다.

**공통 이후 절차**

```bash
# 대상 커밋 SHA를 기록 (REVIEW-001.md 머리말에 넣을 것)
git rev-parse HEAD

# 저장소 위생 직접 확인 — 문서의 주장을 믿지 말고 파일 목록으로 확인
git ls-files
git log --oneline

# 기존 사용자 콘텐츠 보존 확인 (§2.2)
git show 968a105:README.md
head -3 README.md

# 4. 리뷰 작성
#    docs/reviews/REVIEW-001.md

# 5. 커밋 & push
git add docs/reviews/REVIEW-001.md
git commit -m "docs: add TASK-001 independent repository review"
git push -u origin codex/task-001-repo-review
```

## 8. 인계 메모 (Handoff)

**Codex가 알아야 할 배경 — 저장소 밖 정보는 여기 적힌 것이 전부입니다.**

1. 이 프로젝트는 대학 과제에서 출발했고, 장기적으로 상용 제품 가능성이 있습니다.
2. 입력 영상은 의도적으로 어렵습니다 ([`../PRODUCT_SPEC.md`](../PRODUCT_SPEC.md) §3).
3. **채점용 원본은 채점자만 가지고 있습니다.** 채점 피드백으로 학습·튜닝할 수 없습니다.
   이 제약이 평가 설계 전체를 규정합니다.
4. 제품 오너는 개발 경험이 많지 않습니다. **문서가 실제로 이해 가능한지**가 중요한 평가 축입니다.
5. Phase 0에서 아무것도 고정하지 않은 것은 실수가 아니라 의도입니다 (ADR-0001).
   다만 **의도적 미결정과 그냥 빠뜨린 것을 구분**해 주십시오. 후자를 찾는 것이 이 리뷰의 가치입니다.
6. 리뷰 완료 후 다음 단계는 사람 오너의 차단 항목 답변(U-06, U-08, U-11)입니다.
