Phase 0 종료 사실과 제품 오너의 U-08·U-11 답변을 저장소에 공식 반영하고,
**Phase 1 작업 그래프를 실행 가능한 상태**로 만든다.

이 작업이 끝났을 때 존재하게 되는 것:

- `main`의 실제 GitHub 상태(PR #1 병합, PR #2·#3·#4 종료)와 일치하는 `STATUS.md`
- U-08(번역 자막)·U-11(약 2개월·품질 우선)이 **추적 가능하게 기록된** 결정 문서
- 번역 단계가 포함되고 **원문 ASR 평가와 번역 자막 평가가 구분된** Phase 1 계획
- **누가 무엇을 어떤 순서로 착수하는지** 확정된 Phase 1a 실행 순서

**이 TASK는 계획 문서 작업입니다. 구현 코드를 작성하지 않습니다.**

## 2. 제품 오너의 답변 (2026-08-09) — 이 TASK의 근거

사람 제품 오너가 다음을 **명시적으로** 답했습니다.

| ID | 답변 | 함께 확인된 한계 |
|---|---|---|
| **U-08** | **채점 정답은 번역 자막이다** | 번역 **대상 언어는 이 답변에 포함되지 않았습니다.** 추측하지 않고 별도 미해결(U-31)로 등록합니다 |
| **U-11** | **제출까지 약 2개월의 여유가 있으며, 속도보다 최대한 높은 품질을 우선한다** | **정확한 제출 날짜는 아직 확정되지 않았습니다.** 임의의 날짜를 만들지 않습니다 |

**이 답변의 효력 범위 — 두 가지를 분리합니다.**

- **해제되는 것:** Phase 1 **계획 착수**의 차단. 이제 Phase 1 계획을 세우고 Phase 1a에 진입할 수 있습니다.
- **해제되지 않는 것:** **정밀 일정 수립.** 정확한 캘린더 마감일이 확정되어야 마일스톤·버퍼를
  날짜로 고정할 수 있습니다. "약 2개월"은 **운영상 시간 예산**이지 확정된 날짜가 아닙니다.

**U-08·U-11을 ADR로 변환하지 않았습니다.** 두 항목은 사람 오너가 답하는 **사실 확인**이며,
에이전트가 만든 아키텍처 결정이 아닙니다. 기존 U-XX 기록을 삭제하지 않고 답변을 덧붙였습니다.

## 7. 인계 메모 — 독립 리뷰 세션에게

**당신은 이 TASK의 작성자가 아닌 새 독립 Claude Code 세션이어야 합니다** (R8 / §3.1).
작성자의 대화 맥락 없이 저장소 파일과 PR diff만으로 판단하십시오.

**"반영했다"는 Owner의 주장이며, 검증 전에는 완료가 아닙니다** (R10 / §3.5).

검토 시 다음을 의심하십시오.

1. **U-08** — "번역 자막"이 모든 문서에서 일관된가. **번역 대상 언어를 어딘가에서 추측하지
   않았는가.** U-31이 실제로 등록되었는가.
2. **U-11** — "약 2개월"이 **정확한 날짜처럼** 쓰인 곳이 없는가. **Phase 1 계획 착수 차단 해제**와
   **정밀 일정에 날짜가 필요함**이 분리되어 있는가.
3. **ASR ↔ 번역 구분** — 원문 transcript와 번역 subtitle을 혼동하는 서술이 남아 있지 않은가.
   평가도 두 축으로 구분되었는가.
4. **범위 보존** — Phase 2 시각 재구성이 여전히 **과제 필수**인가. 품질 우선이 **무제한 범위 확장**
   이나 **검증 생략**으로 읽히지 않는가.
5. **TASK 번호** — TASK-003·005·006의 기존 의미와 선행 관계가 그대로인가.
6. **상태 정합성** — `STATUS.md`의 PR 상태·TASK 상태가 GitHub 실물과 일치하는가.
   병합된 Phase 0 TASK가 `In review`로 남아 있지 않은가.
7. **역사 기록** — 과거 판정·리뷰 기록이 삭제되거나 다시 쓰이지 않았는가 (R2, ADR-0027).
8. **금지 항목** — 모델·공급자 선택, 날짜·언어 추측, 다른 미해결 항목의 임의 결정이 없는가.
