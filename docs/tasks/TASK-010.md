## 1. 목표

REVIEW-003이 지적한 **M-06의 잔여 모호성 두 건**을 제거한다.

- §3.1 반례 — `inserted_spans`가 어느 시간축에서 판정되는지 알고리즘 A가 명시하지 않아
  같은 입력에서 CER 0.0과 1.0이 모두 나올 수 있었던 문제
- §3.2 반례 — `lines[]` 결합 구분자가 정의되지 않아 같은 cue에서 무음 귀속 문자 수가
  0개와 1개로 갈릴 수 있었던 문제

이 작업이 끝났을 때 존재하게 되는 것: 두 반례 각각에서 **하나의 계산 경로만** 허용되는 규약,
그리고 문서에 고정된 예시로 그 경로를 검증할 수 있는 상태.

## 검토 대상

REVIEW-003 §3.1(`inserted_spans` 시간축 반례), §3.2(`lines[]` 결합 반례)만.
다른 M/R 항목은 REVIEW-003에서 이미 해소로 판정되었으므로 다시 열지 않는다.

## 6. 인계 메모 — 최종 확인 세션에게

**당신은 REVIEW-002·REVIEW-003을 작성한 세션입니다.** 이 TASK를 작성한 주 세션과 다른 세션이므로
최종 확인 자격이 있습니다 (R8 / §3.1).

확인할 것은 **정확히 두 가지**입니다.

1. **반례 1 (§3.1)** — 고정 예시에서 `CER = 0.0` 외의 값이 나오는 해석이 여전히 가능한가?
   알고리즘 A가 `inserted_spans` 판정을 **`to` 시간축에서, source 역투영 전에** 하도록
   순서가 고정되어 있는가?
2. **반례 2 (§3.2)** — 고정 예시에서 `무음 귀속 = 1` 외의 값이 나오는 해석이 여전히 가능한가?
   `canonical_cue_text = norm-v1(lines.join(SPACE))` 규칙이 알고리즘 C·§4.4·§4.5(a) **전부**에서
   동일하게 적용되는가?

**하지 말 것:** 이 두 가지 외의 새로운 발견을 만들지 마십시오. 오너 지시는 "같은 독립 리뷰 세션이
두 반례만 최종 확인"이며, 새로운 전체 문서 리뷰가 아닙니다. 이 브랜치의 파일을 직접 수정하지
마십시오 (§3.3). 병합하지 마십시오 (R1).
