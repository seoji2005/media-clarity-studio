따라서 **어디에도 사용되지 않은 다음 번호인 `TASK-007`** 을 사용합니다.

## 1. 목표

향후 프로젝트 운영을 네 역할 구조로 전환하고, 저장소 문서 전반의 **미래 운영 서술**을
그 구조에 맞춥니다.

이 작업이 끝났을 때 존재하게 되는 것:

- `AGENTS.md` §3에 네 역할과 그 제약이 규칙으로 기록된 상태
- 향후 역할·Owner/Reviewer 배정·작업 절차에서 **Codex / Codex Cloud / GitHub `@codex review`가 제거**된 상태
- **완료된 역사 기록**과 **미래 규칙**이 문서상 명확히 구분된 상태
- 현재·향후 리뷰 배정이 **독립 Claude Code 리뷰 세션**으로 바뀐 상태

## 2. 전환 후 운영 구조

| # | 역할 | 책임 | 저장소 커밋 |
|---|---|---|---|
| 1 | **GPT Work** | 전체 오케스트레이션, 요구사항·우선순위 결정 지원, 작업 분해, Claude에 전달할 정확한 프롬프트 작성, 결과 비교와 사람 오너의 최종 판단 지원 | 하지 않음 |
| 2 | **Claude Code Cloud 주 세션** | Lead Developer. 핵심 설계·구현, 복잡한 디버깅, 성능 최적화. **자기 변경을 스스로 최종 승인하지 않음** | 함 (TASK Owner) |
| 3 | **독립 Claude Code 리뷰 세션** | Independent Reviewer. 작성자와 **반드시 다른 새 세션**. 작성자 대화 맥락을 받지 않고 저장소·해당 TASK·PR diff만 보고 검토. **중요한 PR과 핵심 알고리즘 변경에만** 사용. 리뷰 대상 브랜치의 파일을 직접 수정하지 않음 | 리뷰 문서만 (TASK Reviewer) |
| 4 | **Claude 일반 대화** | 아키텍처 자문, 기술 선택 비교, 막힌 문제의 두 번째 의견. 저장소 구현은 담당하지 않음 | 하지 않음 |

**운영 제약**

1. 향후 역할·배정·절차에서 **Codex / Codex Cloud / GitHub `@codex review` 제거**
2. **Claude 사용량이 제한적** → 주 세션은 고난도 구현에 집중, 독립 리뷰는 중요한 단계에만
3. 작성자와 리뷰어는 **반드시 서로 다른 Claude Code 세션** (R8)
4. **두 세션이 같은 파일을 동시에 수정하지 않음** (R9)
5. 완료 보고만 신뢰하지 않고 **가능한 경우 GitHub 상태와 diff로 검증** (R10)
6. **AI는 병합하지 않으며, 병합 결정은 사람 제품 오너만** 함 (ADR-0009)

**보존 방식:** 삭제하거나 다른 주체가 한 것처럼 바꾸지 않고, **"완료된 역사 기록 / 당시"** 임을
문서에 명시했습니다. 반대로 **과거 TASK 문서 안에 미래 표준 절차로 남아 있던** Codex 지시,
예시 브랜치(`codex/task-001-repo-review`), "다음 리뷰는 Codex가" 류 지시는 제거하거나
현재 운영 구조로 교체했습니다.

## 8. 인계 메모 — 다음 독립 리뷰 세션에게

**당신은 이 변경의 작성자가 아니어야 합니다.** 작성자라면 이 TASK를 검토할 수 없습니다 (R8).
저장소, 이 TASK 문서, PR #1의 diff만 보고 판단하십시오. 작성자에게 물어볼 수 없습니다.

의심할 지점:

1. **미래 규칙과 역사 기록의 경계가 실제로 명확한가** — 역사 기록으로 표시된 문장이
   여전히 미래 지시처럼 읽히는 곳이 남아 있지 않은가.
2. **Codex 참조가 정말로 "역사 기록 문맥에만" 남아 있는가** — 향후 배정·절차 문맥에
   남은 것이 있는가. (`grep -rn -i "codex" --include="*.md" .`)
3. **Owner와 Reviewer가 모든 TASK에서 분리되어 있는가** — 작성자 세션이 리뷰어로
   적혀 있는 곳이 없는가.
4. **U-08·U-11 서술이 PR #1 병합을 자동으로 막는 것처럼 읽히지 않는가** —
   `STATUS.md` §5, `PLAN.md` §2, `DECISIONS.md` §4.1.
5. **§3.2의 "독립 리뷰를 쓴다 / 쓰지 않는다" 경계가 실제로 판정 가능한가** —
   경계에 걸리는 변경을 두 사람이 같게 분류할 수 있는가.
6. **`AGENTS.md` 내부 상호 참조(§3.1~§3.5, R8–R10)가 실재하는가.**
7. **PR #1 설명의 통계가 실제 diff와 일치하는가** — 주장을 믿지 말고 직접 확인하십시오
   (`AGENTS.md` R10 / §3.5).

**하지 말 것:** 이 브랜치의 파일을 직접 고치는 것. 리뷰어는 지적만 합니다 (`AGENTS.md` §3.3).
**병합하지 마십시오.** PR #1은 Draft로 유지하며, 병합은 사람 제품 오너의 결정입니다.
