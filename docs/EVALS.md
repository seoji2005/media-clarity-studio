# EVALS.md — 평가 설계

**"좋아졌는가"를 채점 원본 없이 판단하는 방법.**

마지막 갱신: 2026-08-25 (TASK-005 — 평가 하네스·번역 품질 계약 확정)
상태: **제안됨 (Proposed)** — 전략은 합의 필요, 임계값은 전부 미정

---

## 1. 근본 제약과 신호의 종류

> **채점용 원본 자막과 원본 영상은 채점자만 가지고 있습니다.**
> 우리는 점수를 볼 수 없고, 따라서 **채점 결과로부터 직접 학습하거나 튜닝할 수 없습니다.**

이 제약의 결과:

| 못 하는 것 | 대신 하는 것 |
|---|---|
| 실제 채점 정답과 직접 비교 | **정답을 아는 데이터를 구성해서** 비교 |
| 채점 점수로 하이퍼파라미터 조정 | 여러 신호를 **함께** 보고 조정 |
| 리더보드 순위로 개선 확인 | 조건별 품질 저하 곡선 + 불확실성 구간 |

### 1.1 신호는 하나가 아닙니다

합성 열화는 **주된 개발 신호(primary dev signal)** 이지만 **유일하게 신뢰할 수 있는 신호가 아닙니다.**
하나만 믿으면 그 지표에 과적합합니다. 다음을 **함께** 사용합니다.

| # | 신호 | 정답 필요 | 무엇을 잡는가 | 한계 |
|---|---|---|---|---|
| S1 | 합성 열화 세트 (§3) | 필요 | 조건별 정량 저하, 회귀 탐지 | 실제 입력과 분포가 다를 수 있음 |
| S2 | 자연 난이도 실데이터 (정답 있는 공개 코퍼스) | 필요 | 합성이 아닌 실제 열화 | 우리 입력과 성격이 다를 수 있음 |
| S3 | 무참조 지표·내부 일관성 | 불필요 | 실제 채점 입력에서의 이상 징후 | 속기 쉬움 (§5.5) |
| S4 | 사람 blind 검토 (§6) | 불필요 | 지표가 못 잡는 실패 | 비용이 크고 표본이 작음 |
| S5 | 교차 일치도 (설정·모델 간 불일치) | 불필요 | 불안정한 구간 탐지 | 모두 함께 틀리면 안 잡힘 |
| S6 | 형식·계약 검사 (§4.6) | 불필요 | 결정적 규칙 위반 | 내용 품질은 못 봄 |

**판단 규칙:** 개선 주장은 **S1 + 최소 하나의 다른 신호**가 같은 방향일 때만 합니다.
S1만 좋아지고 S3~S5가 나빠지면 그것은 개선이 아니라 과적합의 징후입니다.

### 1.2 평가가 기능보다 먼저인 이유

측정 도구 없이 만든 개선은 개선인지 알 수 없습니다.
따라서 평가 하네스가 파이프라인보다 먼저 만들어집니다 ([`../PLAN.md`](../PLAN.md) Phase 1a).

## 2. 데이터 설계 — 분할, 누출 방지, 표본 수

**지표 설계보다 먼저 정해야 하는 것이 데이터 분할입니다.**
여기서 실수하면 이후 모든 숫자가 낙관적으로 오염됩니다.

### 2.1 분할 (dev / frozen-test)

| 분할 | 용도 | 접근 빈도 |
|---|---|---|
| `dev` | 반복 개발, 하이퍼파라미터 조정, 실패 분석 | 제한 없음 |
| `frozen-test` | **동결.** 마일스톤에서만 사용 | 사전에 정한 시점에만 |

**frozen-test 규칙**

1. 분할은 **어떤 파이프라인 코드도 작성하기 전에** 확정하고 기록합니다.
2. frozen-test 접근은 **사용 기록(`evals/test_access_log.md`)에 남깁니다.** 누가·언제·왜.
3. frozen-test 결과를 보고 파라미터를 조정하면 **그 시점부터 test는 더 이상 test가 아닙니다.**
   조정했다면 그 사실을 기록하고 해당 분할을 dev로 강등합니다.
4. 접근 횟수 상한과 마일스톤 정의는 미정입니다 (**U-26**).

### 2.2 누출 방지 (Leakage Control)

**분할은 파일 단위가 아니라 출처 단위로 합니다.** 같은 녹음에서 잘라낸 두 조각이
dev와 test에 나뉘어 들어가면 test는 이미 오염된 것입니다.

분할 기준은 다음 **모두**를 만족해야 합니다.

| 기준 | 규칙 |
|---|---|
| 출처(source) | 같은 원본 녹음/영상은 한쪽 분할에만 |
| 화자(speaker) | 같은 화자는 한쪽 분할에만 (화자 정보가 있는 경우) |
| 장면(scene) | 같은 촬영 장면·배경은 한쪽 분할에만 |
| 세션/채널 | 같은 녹음 환경·마이크·카메라는 가능하면 분리 |
| 열화 시드 | dev와 test는 **다른 시드 대역**을 사용 |

**금지**

- 열화를 먼저 적용하고 나서 무작위로 나누기 (같은 원본이 양쪽에 들어감)
- 분할 후 성능이 나빠 보인다고 재분할하기
- test 표본을 dev 실패 분석에 사용하기

### 2.3 표본 수와 보고 단위

**표본 수를 밝히지 않은 지표는 보고로 인정하지 않습니다.**

- 모든 지표는 `n`(표본 수)과 함께 보고합니다.
- **분석 단위(unit of analysis)** 를 명시합니다: 발화 / cue / 초 / 프레임 / 출처.
- 통계 처리의 **군집 단위는 출처(source)** 입니다. 같은 출처의 조각들은 독립이 아닙니다.
- `n`이 사전에 정한 최소치 미만이면 `status: "insufficient_n"`으로 보고하고 **값을 해석하지 않습니다.**
- 최소 표본 수는 미정입니다 (**U-26**).

### 2.4 계층 보고 (Stratified Reporting)

**평균 하나는 실패를 숨깁니다.** 다음 축으로 나눠 보고합니다.

```
언어 × 열화 종류 × 열화 강도 × 겹침 유무 × 출처 유형
```

- 어떤 계층에서 `n`이 부족하면 그 계층은 "표본 부족"으로 표시합니다. 합쳐서 감추지 않습니다.
- 전체 평균이 좋아져도 **특정 언어·강도에서 나빠졌다면 리포트 상단에 표시**합니다.

### 2.5 seed 코퍼스 확보 — 조사는 에이전트, 승인은 사람

**이전 판에서 U-06은 순환 의존이었습니다.** 사람 오너에게 "코퍼스를 어떻게 구할지"를 물으면서,
그 답이 없으면 아무것도 못 한다고 적어 두었습니다. 개발 경험이 적은 오너에게
조사 자체를 떠넘긴 셈입니다. 역할을 다음과 같이 나눕니다.

| 주체 | 하는 일 |
|---|---|
| **에이전트 (조사)** | 후보 코퍼스 조사, 라이선스 조건 정리, 합성 데이터 대안 조사, 장단점 비교표 작성 |
| **사람 오너 (승인)** | 제약 승인(허용 라이선스 범위·비용 상한·과제 규정), 최종 선택 |

- 조사는 **차단되지 않습니다.** 오너의 답변 없이 지금 시작할 수 있습니다 (TASK-003 후보).
- 오너에게는 **조사 결과를 놓고 고르는 결정**만 요청합니다 (U-06).
- 조사 산출물: 후보별 `{ 이름, 언어, 규모, 정답 형식, 라이선스, 재배포 가능성, 비용, 위험 }`.

#### 2.5.1 U-06 승인 계약

사람 제품 오너는 TASK-003 결과를 바탕으로 다음 최소 조합을 승인했다.

| 역할 | 선택 | 고정 범위 |
|---|---|---|
| 일본어 clean seed | [Common Voice Scripted Speech 26.0 Japanese](https://mozilladatacollective.com/datasets/cmqim4lxy00tunr07cjkcupeg) | dataset ID `cmqim4lxy00tunr07cjkcupeg`, 14.35 GB. local-only cache; 재호스팅·재공유·재식별 금지 |
| 영어 seed | [LibriSpeech SLR12](https://www.openslr.org/12/) | `dev-clean`, `dev-other`, `test-clean`, `test-other` 4개 archive만. CC BY 4.0 고지 보존 |
| 일본어↔영어 전환 | 위 두 seed의 source/speaker-disjoint 발화를 deterministic recipe로 합성 | 원본 분할을 넘나드는 재사용 금지; recipe·seed·source ID 기록 |
| 자연 겹침 | CHiME-6 dev | cpWER 구현 시점까지 **유예**. 현재 다운로드 금지 |
| 실제 코드스위칭 JECS | 제외 | 비상업·개인 사용 및 재배포 금지 조건이 장기 상업화 경계와 충돌 |

이 승인은 **데이터 다운로드·계정 생성·저장소 포함을 승인하지 않는다.** 실제 확보 작업은 고정 archive,
약관 snapshot, hash, local cache 경로, 삭제 rehearsal을 갖춘 별도 Gate H로 수행한다.

### 2.6 seed 코퍼스 요구사항

| 요구 | 이유 |
|---|---|
| 정답 전사가 확정적일 것 | 정답이 흔들리면 모든 지표가 무의미 |
| `ReferenceBundle/v1`로 표현 가능할 것 | 계약 미충족 시 계산 불가 지표가 생김 |
| 여러 언어 포함 | 다국어 전환 평가에 필요 |
| 여러 화자·성별·연령 | 특정 음성에 과적합 방지 |
| 겹치는 발화 정답이 화자별로 분리되어 있을 것 | cpWER의 전제 (§4.2) |
| 원래 깨끗할 것 | 열화를 우리가 통제해야 함 |
| 사용이 허용되고 재배포 경계가 명확할 것 | 라이선스·서비스 약관 (`AGENTS.md` §8) |
| 영상 트랙 포함 (일부) | 시각 도메인 평가에 필요 |

## 3. 합성 열화 전략 (Synthetic Degradation)

### 3.1 기본 아이디어

```
깨끗한 원본 + ReferenceBundle (정답)
        │
        ├─► 열화 레시피 적용 (강도 조절, 시드 고정, TimeMapping 생성)
        │           │
        │           ▼
        │      어려운 입력  ──► 파이프라인 ──► 결과
        │                                       │
        └──────────── 비교 (시간축 변환 후) ◄────┘
                       │
                       ▼
              지표 + 저하 곡선 + 불확실성
```

**핵심:** 우리가 열화를 직접 만들었기 때문에 정답을 압니다.
다만 §1.1대로 **이것만 보지 않습니다.**

### 3.2 열화 레시피

각 레시피는 **강도 0(없음) ~ 5(극심)** 로 조절 가능해야 합니다.

**오디오**

| ID | 이름 | 모사하는 문제 | 조절 축 | 시간 변경 |
|---|---|---|---|---|
| D-A1 | `stationary_noise` | 지속적 배경 잡음 | SNR (dB) | 없음 |
| D-A2 | `burst_noise` | 갑작스러운 큰 소리 | 빈도, 피크 | 없음 |
| D-A3 | `speaker_overlap` | 겹치는 발화 | 겹침 비율, 간섭 크기 | 없음 |
| D-A4 | `long_silence` | 긴 무음 삽입 | 길이, 횟수 | **있음** |
| D-A5 | `bandwidth_reduction` | 전화 수준 대역 | 컷오프 | 없음 |
| D-A6 | `codec_artifact` | 저비트레이트 압축 | 비트레이트 | 없음 |
| D-A7 | `reverb` | 울리는 공간 | 잔향 시간 | 없음 |
| D-A8 | `clipping` | 과입력 왜곡 | 클리핑 비율 | 없음 |
| D-A9 | `language_switch` | 다국어 전환 | 전환 횟수·지점 | **있음** |
| D-A10 | `level_instability` | 음량 급변 | 변동 폭 | 없음 |

**영상 (Phase 2)**

| ID | 이름 | 모사하는 문제 | 조절 축 | 시간 변경 | **`degradation_kind` (정답)** |
|---|---|---|---|---|---|
| D-V1 | `gaussian_blur` | 초점 흐림 | 커널 크기 | 없음 | `blur` |
| D-V2 | `motion_blur` | 움직임 흐림 | 길이·각도 | 없음 | `blur` |
| D-V3 | `mosaic` | 모자이크 처리 | 블록 크기·영역 | 없음 | `mosaic` |
| D-V4 | `downscale_upscale` | 해상도 축소 후 복귀 | 배율 | 없음 | `low_resolution` |
| D-V5 | `compression_artifact` | 블록·링잉 | 품질 파라미터 | 없음 | `compression` |
| D-V6 | `sensor_noise` | 저조도 노이즈 | 세기 | 없음 | `sensor_noise` |
| D-V7 | `frame_degradation` | 프레임 드롭·중복 | 드롭 비율 | **있음** | 해당 없음 — 영역 마스크를 만들지 않는 시간축 열화 (`TimeMapping`으로 표현) |

> **마지막 열이 `recipe_id → degradation_kind` 대응표입니다** (REVIEW-002 M-05).
> 허용값은 `DegradedRegion/v1.degradation_kind`와 **동일한 집합**이며 새 종류를 만들지 않습니다
> ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.3).
>
> **영역 마스크를 만드는 레시피는 `recipe_id`와 `degradation_kind`를 반드시 함께 기록합니다.**
> 종류를 비워 두거나 이 표와 다른 값을 넣으면 **계약 검증 실패**이며, 그 번들은 평가에 투입하지 않습니다.
> D-V7처럼 영역 마스크가 없는 레시피는 `degradation_masks[]` 항목 자체를 만들지 않습니다.

### 3.3 레시피의 필수 출력

각 레시피는 열화본만 만드는 것이 아니라 **정답 갱신물도 함께** 만듭니다.

| 조건 | 반드시 반환해야 하는 것 |
|---|---|
| 시간 변경 열화 (D-A4, D-A9, D-V7) | `TimeMapping/v1` — 없으면 타임스탬프 지표가 조용히 틀림 |
| 공간 열화 (D-V1~D-V6) | `RegionMask/v1` — 이동 영역이면 keyframe 2개 이상 |
| 겹침 삽입 (D-A3) | 추가된 화자의 `speaker_stream`과 `overlap_spans` |
| 언어 전환 (D-A9) | 갱신된 `language_spans` (`switch_kind` 포함) |
| 무음 삽입 (D-A4) | `inserted_spans` (`kind: "silence"`) — 이 구간은 정답상 무음 |

**`TimeMapping`을 반환하지 않는 시간 변경 열화는 평가에 투입할 수 없습니다.**

### 3.4 조합 프로파일

```
P-EASY    : D-A1(1) + D-A5(1)
P-MEDIUM  : D-A1(3) + D-A3(2) + D-A9(1) + D-A6(2)
P-HARD    : D-A1(4) + D-A2(3) + D-A3(4) + D-A4(3) + D-A9(3) + D-A6(4)
P-VISUAL  : D-V1(3) + D-V3(3) + D-V4(3) + D-V5(3)
```

> 위 수치는 **예시이며 확정이 아닙니다.** 실제 입력을 관찰한 뒤 조정합니다 (U-17).

### 3.5 재현성 규칙

- 모든 열화는 **시드 고정**입니다. dev와 test는 다른 시드 대역을 씁니다 (§2.2).
- 생성된 세트는 `dataset_id`로 식별하고 레시피·시드·`ReferenceBundle` 버전을 기록합니다.
- 레시피가 바뀌면 `dataset_id`가 바뀝니다. **다른 `dataset_id`의 점수를 비교하지 않습니다.**

## 4. 자막 지표 — 계산 규약 (Metric Protocol)

**지표 이름만으로는 재현되지 않습니다.** 구현자가 같은 숫자를 얻으려면 다음이 필요합니다.
각 지표마다 **필요 정답 / 매칭 규칙 / 분모 / 제외 규칙 / 미지원 조건**을 정의합니다.

**정답 축이 둘입니다 — 먼저 읽으십시오**

채점 정답은 **번역 자막**입니다 ([`PRODUCT_SPEC.md`](PRODUCT_SPEC.md) §2.0, U-08).
그래서 자막 지표는 **두 축**으로 나뉩니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0.1).

| 축 | 가설 | 정답 | 지표 |
|---|---|---|---|
| **원문 축 (`source`)** | `Transcript/v1` (`asr` 산출) 또는 `SubtitleDocument(text_axis="source")` | `speaker_streams[].utterances[].text` · `reference_cues[]` 중 `reference_axis: "source"` | **§4.1~§4.6** |
| **번역 축 (`target`)** | `TranslatedTranscript/v1` (`translate` 산출) 또는 `SubtitleDocument(text_axis="target")` | `reference_cues[]` 중 `reference_axis: "target"` + `target_language` | **§4.7** |

| # | 규칙 |
|---|---|
| **Y-1** | **텍스트 내용 정확도 지표(§4.1 WER·CER, §4.2 cpWER, §4.5 언어 식별)는 원문 축 전용입니다.** 이 값들을 **번역 품질로 보고하지 않습니다** |
| **Y-2** | 가설과 정답의 축이 **다르면 계산하지 않습니다.** 축이 어긋난 비교는 오류이지 낮은 점수가 아닙니다 |
| **Y-3** | 두 축의 값을 **하나의 숫자로 합치지 않습니다** (ADR-0015). `EvalReport`는 `metrics_by_axis`로 나눠 담습니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §7.6) |
| **Y-4** | 현재 제품의 번역 축은 **`target_language: "ko"`** 입니다 (U-31 해소). 누락·`undetermined`·비-`ko` 정답/가설은 계산 가능한 한국어 번역 축으로 취급하지 않습니다 |
| **Y-5** | **축과 무관한 지표(§4.3 타임스탬프, §4.4 무음 환각, §4.6 형식)는 두 축 모두에 적용할 수 있습니다.** 타이밍과 형식은 언어에 의존하지 않기 때문입니다. 이때 **어느 축의 자막을 쟀는지 반드시 표기**합니다 (§4.7 (c)) |

### 4.0 공통 전처리

**(1) 시간축 정렬** — 가설(hypothesis)은 열화 시간축, 정답은 원본 시간축에 있습니다.

```
비교 전 반드시: hypothesis 시간 --TimeMapping--> source 시간
```

- `is_invertible: false`인 매핑은 해당 조건의 시간 관련 지표를 **미지원** 처리합니다.
- `inserted_spans`(원본에 대응 없음)의 처리는 지표별로 §4.2~§4.5에 명시합니다.

**(2) 텍스트 정규화 — `norm-v1`** (규칙 내용은 U-19)

정규화 규칙 집합은 **버전을 가집니다.** 규칙이 바뀌면 버전을 올리고,
**다른 버전으로 계산된 점수를 비교하지 않습니다.**

| 항목 | 규정 방식 |
|---|---|
| 대소문자 | 언어별 fold 규칙 |
| 문장부호 | 제거 여부를 언어별로 지정 |
| 숫자·기호 표기 | 정규형 지정 (예: 숫자를 어느 형태로 통일할지) |
| 공백 | 연속 공백 축약, 앞뒤 제거 |
| 유니코드 | 정규화 형식 지정 (NFC/NFKC 중 택일, 언어별 예외 명시) |
| 토큰 단위 | 공백 구분 언어 → 단어 / CJK·태국어 등 → 문자(grapheme cluster) |

**토큰 단위는 언어별로 고정하고 리포트에 표기합니다.** 언어마다 다른 단위를 쓰면
언어 간 수치를 직접 비교할 수 없으므로, 언어별로만 비교합니다.

**(3) WER의 토큰 단위와 CER의 단위는 별개입니다.** 위 표의 "토큰 단위"는 **WER 전용**입니다.
CER의 단위는 §4.0.1 알고리즘 D가 고정합니다.

### 4.0.1 결정적 공통 규칙 — 두 구현자가 같은 값을 얻기 위한 것

**이 절의 알고리즘은 여러 지표가 공유합니다.** 지표마다 다르게 구현하면 값이 갈립니다
(REVIEW-002 M-06). 아래 규칙은 **해석의 여지가 하나만 남도록** 적었습니다.

#### 알고리즘 A — `inserted_spans` 제외는 **`to` 시간축에서, 문자열 결합 전에** 수행한다

**전제 — `inserted_spans`는 `to` 시간축에 있습니다.**
`TimeMapping.inserted_spans[].to_start`/`to_end`는 **`to_timebase`의 반개구간 `[to_start, to_end)`**
입니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §2.3). `from_timebase`(source) 쪽에는 애초에 대응이
없는 구간이므로, **삽입 구간 판정은 반드시 `to` 시간축에서 먼저** 하고, 그 뒤에 살아남은 문자만
source로 역투영합니다. 순서를 바꿔 가설을 먼저 source로 옮긴 뒤 판정하면, 삽입 구간의 문자는
**source 대응 시각 자체가 없어 판정이 불가능**해지고 구현마다 다른 값이 나옵니다
(REVIEW-003 §3.1 — 이 반례로 CER 0.0/1.0이 모두 나올 수 있었습니다).

편집거리는 전역 연산이므로, 이어붙인 뒤에 특정 구간의 기여만 빼는 연산도 정의되지 않습니다.
따라서 **제거를 먼저** 합니다. 아래 순서를 그대로 따르며, 다른 순서로 구현할 수 없습니다.

```
A1. 가설의 각 문자(또는 토큰)에 시각을 부여한다 — **가설 고유의 시간축(보통 to_timebase)에서.**
    ← 알고리즘 C
A2. 가설의 시간축이 TimeMapping.to_timebase와 다르면, 정의된 변환 규칙으로 to_timebase로
    옮긴다. 변환 규칙이 없으면 이 지표를 "미지원" 또는 "계약 검증 실패"로 보고하고,
    시각을 추측하지 않는다.
A3. inserted_spans[].to_start/to_end는 to 시간축의 반개구간 [to_start, to_end)이다.
    각 가설 문자의 중앙 시각을 **to 시간축에서** 어떤 inserted_span 안에 있는지 판정한다.
    이 판정은 **source로 옮기기 전에** 한다.
A4. inserted_span 안에 있는 문자를 "제외 대상"으로 표시한다. 제외는 source 대응 시각의
    존재 여부와 무관하게 이루어진다 — 애초에 그 구간은 source 대응이 없다.
A5. 제외 대상 문자를 가설에서 제거한다.                   ← 여기까지가 "결합 전"
A6. **남은(제외되지 않은) 문자만** TimeMapping으로 source 시간축에 역투영한다.
    (정답과의 정렬·시간순 결합을 위해 필요. 제외된 문자는 역투영하지 않는다 —
    애초에 대응이 없다)
A7. 남은 가설 문자를 시간(source) 오름차순으로 이어붙여 가설 문자열 H를 만든다.
    동일 시각이면 stream_id 오름차순, 그 다음 원래 등장 순서로 정렬한다.
A8. 정답도 같은 방식으로 이어붙여 R을 만든다. (정답은 ReferenceBundle.source_timebase)
A9. R과 H로 편집거리를 계산한다.
```

경계는 전부 **`[start, end)` 반개구간**으로 고정합니다.

- **제거된 문자는 조용히 폐기되지 않습니다.** §4.4 환각 지표(무음 환각률·환각 사건률)의
  입력으로 별도 평가됩니다. 버리는 것이 아니라 옮기는 것입니다.
- 이어붙인 뒤에 구간 기여를 차감하는 방식(정렬 후 삽입 오류만 빼기)은 **쓰지 않습니다.**
  두 방식의 값이 다르므로 하나만 남깁니다.

**고정 예시 (REVIEW-003 §3.1 반례 해소 확인용)**

```
정답 R = "a" (source [0,1))
TimeMapping: source [0,1) -> degraded/to [0,1)
inserted_spans: to [1,2), kind="silence"
가설:
  "a" @ to [0,1)
  "x" @ to [1,2)
```

이 입력에서 유일하게 허용되는 계산 경로:

1. **A1** — "a"의 중앙 시각 = to 0.5초, "x"의 중앙 시각 = to 1.5초 (둘 다 `to` 시간축)
2. **A2** — 가설 시간축 = `to_timebase` — 변환 불필요
3. **A3–A4** — "x"의 중앙 시각(to 1.5)이 `inserted_span [1,2)` 안에 있음 → "x"를
   **제외 대상**으로 표시. "a"의 중앙 시각(to 0.5)은 어떤 span에도 없음 → 제외 대상 아님
4. **A5** — "x" 제거. 이 시점의 가설 = `["a"]`
5. **A6** — "a"를 source로 역투영 → source 0.5초 (identity 매핑)
6. **A7–A8** — H = `"a"`, R = `"a"`
7. **A9** — 편집거리 0

**결과:** WER/CER용 `H = "a"`, **`CER = 0 / 1 = 0.0`**.
`"x"`는 제거된 뒤에도 **무음·환각 지표의 입력으로는 남습니다** (제거 = 조용한 폐기가 아닙니다).

> **이 예시에서 `CER = 1.0`(H=`"ax"`)이 나오는 해석은 위 순서를 어겼을 때만 가능하며,
> 문서상 허용되지 않습니다.** A3의 판정이 `to` 시간축에서 먼저 일어나므로, source 대응이
> 없다는 이유로 "x"의 제외 여부를 판정하지 못하는 경로가 없습니다.

#### 알고리즘 B — IoU 매칭은 **전역 1:1 최적 할당**이다 (greedy 아님)

`§4.3 cue 매칭`과 `§5.1 영역 매칭`이 함께 씁니다.

```
B1. 후보 쌍 (정답 i, 가설 j)의 IoU를 모두 계산한다.
B2. IoU < T_match 인 쌍은 후보에서 제거한다.
B3. 남은 후보에 대해 총 IoU 합을 최대화하는 1:1 할당을 구한다.
    (Hungarian / Kuhn-Munkres 등 전역 최적 할당. greedy 순차 선택 금지)
B4. 할당되지 않은 정답 = 누락, 할당되지 않은 가설 = 허위.
```

**동점 처리 (tie-break) — 총 IoU 합이 같은 해가 여럿일 때, 아래 순서로 하나를 고른다**

| 순위 | 기준 |
|---|---|
| 1 | 매칭된 쌍의 **개수가 많은** 해 |
| 2 | 매칭 쌍의 **시작 시각(영역이면 마스크 시작 프레임) 절대 오차 합이 작은** 해 |
| 3 | 정답을 시작 시각 오름차순으로 정렬했을 때, **앞선 정답에 더 작은 인덱스의 가설이 배정된** 해 (사전식 최소) |
| 4 | 그래도 같으면 정답·가설 **ID의 사전식 순서** |

> 4단계까지 가면 해가 유일합니다. 구현은 이 순서를 그대로 적용합니다.

#### 알고리즘 C — 문자·단어 타이밍이 없을 때 문자 시각을 파생하는 규칙

어댑터가 단어 타이밍을 제공하지 않으면(§7.3.1) cue 시작·종료만 있습니다.
그때 문자 시각은 **cue 구간 내 균등 배분**으로 파생합니다.

**C0. `lines[]` 결합 규칙 — canonical cue text**

문자 시각을 파생하기 전에, cue의 텍스트를 **하나의 결정적 문자열**로 고정합니다.
이 문자열(`canonical_cue_text`)은 문자 시각 파생(C1–C3)과 **§4.4 무음 귀속이 동일하게**
사용합니다 (REVIEW-003 §3.2 — 이전 판은 구분자를 정하지 않아 무음 귀속 문자 수가 0개와
1개로 갈릴 수 있었습니다).

> **§4.5(a) 언어 지표는 이 문자열을 쓰지 않습니다.** cue에는 언어 구간이 없고 계보로
> 계산할 수도 없어 `SubtitleDocument` 가설의 언어 지표 자체가 **미지원**입니다
> (§4.5(a), REVIEW-025 D-03). 이전 판이 여기에 남겨 둔 언어 투영 문구를 철회합니다.

```
raw_cue_text       = lines.join(U+0020 SPACE)
canonical_cue_text = norm-v1(raw_cue_text)
```

규칙:

1. **모든 인접 `lines[]` 사이에 정확히 한 개의 U+0020 SPACE**를 삽입합니다. 구분자
   없이 이어붙이거나(`""`), 다른 문자로 결합하지 않습니다.
2. 줄 내용을 **암묵적으로 trim하거나 빈 줄을 삭제하지 않습니다.** `lines[]`에 있는
   그대로 결합합니다.
3. `join` 후 **`norm-v1`을 정확히 한 번** 적용합니다. 줄 단위로 먼저 정규화한 뒤
   결합하지 않습니다.
4. 알고리즘 C의 grapheme cluster 수 **N은 `canonical_cue_text`에서 계산**합니다
   (알고리즘 D와 같은 단위).
5. `norm-v1` 적용 후 남은 구분자(정규화 규칙이 공백을 축약하지 않는 언어라면 그대로
   남은 SPACE)도 **grapheme 시퀀스의 일부**입니다. 별도로 건너뛰지 않습니다.
6. **문자 중앙 시각과 무음 귀속이 같은 `canonical_cue_text`를 사용**합니다. 지표마다
   다른 결합 방식을 쓰지 않습니다. `language_spans` 시간 투영은 이 목록에 **없습니다** —
   §4.5(a)가 `SubtitleDocument` 가설에서 그 지표를 미지원으로 두기 때문입니다.
7. 줄 단위 구간을 결합 오프셋으로 바꾸는 지표는 **앞선 줄들의 길이
   합 + 그 사이 삽입된 구분자 수**를 더합니다. 예: `canonical_cue_text` 안에서
   2번째 줄의 시작 오프셋은 `len(정규화된 line[0]) + 1`입니다 (+1은 삽입된 SPACE).
   **cue에는 저장된 `language_spans`가 없고, 계보를 따라 계산하지도 않습니다**
   ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0.2 L-2, §4.5(a)). 이 규칙은 줄 단위 구간을
   쓰는 **다른** 지표를 위한 공통 오프셋 규약입니다.
8. **삽입된 줄 구분자 자체는 어느 구간에도 자동으로 포함되지
   않습니다.** 구분자 위치는 인접 줄 어느 쪽에도 귀속시키지 않고 비워 둡니다.
   구분자는 표시용 인공 문자이며 upstream 원문 증거가 아니기 때문입니다.
9. 이 규칙은 **공통 규칙**입니다. 다른 지표가 줄을 서로 다른 구분자로 결합하는 것을
   금지합니다.

```
C1. 어댑터가 문자 타이밍을 제공하면 그대로 쓴다.                    (우선순위 1)
C2. 단어 타이밍만 제공하면, 각 단어 구간 안에서 그 단어의 문자를
    균등 배분한다.                                                  (우선순위 2)
C3. 둘 다 없으면 canonical_cue_text를 기준으로 cue 구간 안에서
    균등 배분한다.                                                  (우선순위 3)

    cue = [t_start, t_end), canonical_cue_text의 grapheme cluster 수 = N (N ≥ 1)
    d   = (t_end - t_start) / N
    k번째 grapheme(0-based)의 구간   = [t_start + k·d, t_start + (k+1)·d)
    k번째 grapheme의 대표 시각(중앙) = t_start + (k + 0.5)·d
```

- **N = 0(빈 cue, 즉 `lines[]`가 전부 빈 문자열)이면 그 cue는 문자 귀속에서 제외**하고
  그 사실을 보고합니다.
- **어떤 파생 단계를 썼는지(C1/C2/C3) 리포트에 표기**합니다. 값이 아니라 신뢰도가
  달라집니다.

> 이 규칙은 **§4.1(알고리즘 A의 A1)과 §4.4 귀속이 동일하게** 사용합니다.
> 지표마다 다른 파생 규칙을 쓰지 않습니다.
> **§4.5(a)는 여기에 포함되지 않습니다** — `SubtitleDocument` 가설의 언어 지표는
> 미지원이고, raw `Transcript` 가설의 문자→시간 투영도 아래 §4.5(a)가 정한 대로
> **후속 계약 전까지 미지원**입니다 (REVIEW-025 D-03).

**고정 예시 (REVIEW-003 §3.2 반례 해소 확인용)**

```
가설 cue = [0,4)
lines = ["A", "B"]
문자·단어 타이밍 없음
이 예시의 norm-v1은 U+0020을 보존한다고 가정
정답 무음 = [3.2,4)
```

이 입력에서 유일하게 허용되는 계산 경로:

1. `raw_cue_text = "A" + " " + "B" = "A B"`
2. `canonical_cue_text = norm-v1("A B") = "A B"` (이 예시의 norm-v1은 값을 바꾸지 않음)
3. N = 3 (grapheme: `A`, ` `, `B`)
4. d = 4 / 3 ≈ 1.3333초
5. k=0 ("A"): 구간 `[0, 1.3333)`, 중앙 시각 ≈ **0.667초**
6. k=1 (" "): 구간 `[1.3333, 2.6667)`, 중앙 시각 = **2.0초**
7. k=2 ("B"): 구간 `[2.6667, 4.0)`, 중앙 시각 ≈ **3.333초**
8. "B"의 중앙 시각(3.333)이 정답 무음 `[3.2, 4)` 안에 있음 → **무음 귀속 문자 수 = 1**

> **이 예시에서 `"AB"`·`N=2`·무음 귀속 `0개`가 나오는 해석은 문서상 불가능합니다.**
> C0 규칙에 따라 결합 시 반드시 SPACE가 삽입되고, 그 SPACE도 grapheme 시퀀스에
> 포함되므로 N은 항상 3입니다.

#### 알고리즘 D — CER의 단위는 정규화 후 **Unicode grapheme cluster**다

```
D1. norm-v1로 정규화한다 (유니코드 정규화 형식 포함 — §4.0(2)).
D2. 정규화된 문자열을 Unicode 확장 자소 클러스터(extended grapheme cluster,
    UAX #29)로 분할한다. 코드포인트 단위나 UTF-16 코드유닛 단위가 아니다.
D3. 그 클러스터 열에 대해 Levenshtein 편집거리를 계산한다.
D4. 분모 = 정답의 grapheme cluster 수.
```

- **결합 문자·이모지 변형 열·한글 조합형은 하나의 클러스터**로 셉니다.
- 이 단위는 **모든 언어에 동일하게** 적용됩니다. WER의 토큰 단위와 달리 언어별로 바뀌지 않습니다.
- 따라서 **CER은 언어 간 비교가 가능**하고, WER은 언어별로만 비교합니다.

### 4.1 텍스트 정확도 — WER과 CER (**분리해서 보고**) *(원문 축 전용)*

> **이 절은 원문 축(`source`) 지표입니다** (§4 Y-1). 여기서 나오는 WER·CER은
> **`asr`의 원문 인식 정확도**이며 **번역 품질이 아닙니다.**
> 번역 축은 §4.7입니다. 두 값을 서로 대신 쓰지 않습니다.

WER과 CER은 **단위도 분모도 다릅니다.** 한 행에 묶으면 공백 구분 언어에서
CER의 단위가 정의되지 않습니다 (REVIEW-002 M-06 ⑤). 그래서 표를 나눕니다.

**(a) WER — 단어 오류율**

| 항목 | 규정 |
|---|---|
| 가설 축 | **원문**: `Transcript/v1` 또는 `SubtitleDocument(text_axis="source")` |
| 필요 정답 | **원문 축만**: `speaker_streams[].utterances[].text` 또는 `reference_cues[].lines[]` 중 **`reference_axis: "source"`** 인 것 |
| 단위 | **§4.0(2)의 언어별 토큰 단위** (공백 구분 언어 → 단어). CJK·태국어 등 토큰 단위가 문자인 언어에서는 **WER을 보고하지 않고 CER만** 보고합니다 |
| 매칭 | **알고리즘 A**로 제외 처리 후 이어붙인 R·H를 비교 (구간 매칭 불필요) |
| 거리 | Levenshtein 편집거리 (삭제·삽입·치환 분해 보고) |
| 분모 | **정규화 후 정답 토큰 수** |
| 제외 | `inserted_spans` 구간의 가설 텍스트는 **알고리즘 A로 결합 전에 제거**하고, §4.4 환각 지표로 별도 계산 |
| 미지원 | `norm-v1`에 해당 언어 규칙이 없을 때 / 토큰 단위가 문자인 언어 |
| 보고 | 언어별 분리 + 삭제/삽입/치환 비율 + **언어별 토큰 단위 표기** |

**(b) CER — 문자 오류율**

| 항목 | 규정 |
|---|---|
| 가설 축 | (a)와 동일 — **원문** |
| 필요 정답 | (a)와 동일 — **원문 축만** |
| 단위 | **정규화 후 Unicode grapheme cluster** — **알고리즘 D**. 언어와 무관하게 동일 |
| 매칭 | (a)와 동일 (**알고리즘 A**) |
| 거리 | grapheme cluster 열의 Levenshtein 편집거리 |
| 분모 | **정규화 후 정답 grapheme cluster 수** |
| 제외 | (a)와 동일 |
| 미지원 | `norm-v1`에 해당 언어 규칙이 없을 때 |
| 보고 | **모든 언어에 대해 보고.** 언어별 분리 + 삭제/삽입/치환 비율 |

> **삽입 오류가 급증하면 환각 신호입니다.** 총합만 보지 말고 분해를 봅니다.
> WER과 CER을 **하나의 숫자로 합치지 않습니다** (ADR-0015).
> **원문 축 CER이 좋다는 것은 번역이 좋다는 뜻이 아닙니다.** 채점 대상은 번역 자막이며,
> 그 품질은 §4.7에서 **따로** 잽니다 (T-3).

### 4.2 겹치는 발화 — cpWER *(원문 축 전용)*

> **원문 축 지표입니다** (§4 Y-1). `speaker_streams[]`는 언제나 원문 축이기 때문입니다
> ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0.1 X-2).

| 항목 | 규정 |
|---|---|
| 필요 정답 | `speaker_streams[]`가 **화자별로 분리**되어 있고 `is_complete: true` |
| 필요 가설 | `Transcript.streams[]`가 2개 이상 (겹침 표현 가능한 어댑터) |
| 절차 | ① 정답 각 화자 스트림을 시간순 연결 → 참조 문자열 집합 R<br>② 가설 각 스트림을 시간순 연결 → 가설 문자열 집합 H<br>③ \|R\|≠\|H\|이면 **빈 문자열로 패딩**하여 크기를 맞춤<br>④ 모든 1:1 대응 중 **총 편집거리 최소인 순열** 선택<br>⑤ cpWER = (최소 총 편집거리) / (전체 정답 토큰 수) |
| 분모 | 모든 화자 스트림의 정답 토큰 합계 |
| 제외 | `is_complete: false`인 화자 스트림은 **분모·분자 모두에서 제외**하고 그 사실을 보고 |
| 미지원 | 가설 스트림이 1개뿐일 때 (`supports_overlap_streams: false`) |

**미지원 시 대체 지표 — 겹침 내용 포함률 (overlap content coverage)**

단일 스트림 어댑터에서도 계산 가능한 완화 지표입니다.

```
겹침 구간의 정답 토큰 중, 시간 허용창(±W초) 안의 가설 어딘가에 나타난 비율
```

- 화자 귀속을 요구하지 않습니다. "내용이 어디든 나왔는가"만 봅니다.
- `W`는 리포트에 명시합니다. **cpWER의 대체물이지 동등물이 아닙니다.** 두 수치를 섞어 비교하지 않습니다.

**추가 보고**

- 겹침 강도(D-A3 severity)별 곡선
- 겹침 구간 누락률 = 겹침 구간 정답 토큰 중 가설에 전혀 없는 비율
- 화자 귀속 정확도 — diarization 채택 시에만 (U-15)

### 4.3 타임스탬프 정렬 *(두 축 모두 — 축 표기 필수)*

> 타이밍은 언어에 의존하지 않으므로 원문 축과 번역 축 **모두**에 적용합니다 (§4 Y-5).
> 계산할 때 어느 축의 자막을 쟀는지 **반드시 표기**하고, 축별로 나눠 보고합니다.

| 항목 | 규정 |
|---|---|
| 필요 정답 | `reference_cues[]` (또는 utterance 경계) |
| 단위 | cue |
| 매칭 | 시간축 정렬 후, 정답 cue와 가설 cue를 **알고리즘 B(전역 1:1 최적 할당)** 로 매칭. IoU = 교집합/합집합 (초). **greedy 순차 선택을 쓰지 않습니다.** 동점 처리는 알고리즘 B의 tie-break 표를 그대로 적용 |
| 매칭 임계 | IoU ≥ `T_match` 인 쌍만 매칭으로 인정 (기본 제안 0.3, 리포트에 명시) |
| 분모 (오차 통계) | **매칭된 쌍의 수** |
| 분모 (누락률) | **전체 정답 cue 수** |
| 분모 (허위율) | **전체 가설 cue 수** |
| 제외 | `inserted_spans` 내부에만 존재하는 가설 cue는 타이밍 통계에서 제외 (§4.4에서 계산) |
| 미지원 | `TimeMapping.is_invertible: false` |

**반드시 함께 보고하는 3종** — 하나만 보면 게임할 수 있습니다.

| 지표 | 왜 필요한가 |
|---|---|
| 매칭 쌍의 시작/종료 오차 (중앙값, p95) | 정렬 정확도 |
| 누락률 (매칭되지 않은 정답 cue 비율) | **cue를 적게 내면 오차가 좋아지는 것을 막음** |
| 허위율 (매칭되지 않은 가설 cue 비율) | 과다 생성을 막음 |

**드리프트**

- 서명된(signed) 시작 오차를 시간에 대해 선형회귀 → **기울기(초/분)** 보고
- 영상을 3등분해 구간별 중앙값 오차도 함께 보고 (누적 오차는 초반만 보면 안 보임)

**동기 이탈률:** |시작 오차| > `T_sync` 인 매칭 쌍 비율. `T_sync` 기본 제안 0.5초, 리포트에 명시 (U-18).

### 4.4 무음 구간 오류 — **최우선 지표** *(두 축 모두 — 축 표기 필수)*

> **`asr`만 환각하는 것이 아닙니다.** `translate`도 없는 내용을 만들 수 있으므로
> 이 지표는 원문 축과 번역 축 **모두**에서 계산합니다 (§4 Y-5). 축을 표기합니다.

| 항목 | 규정 |
|---|---|
| 필요 정답 | `speech_mask.segments[]` + (합성 시) `TimeMapping.inserted_spans` |
| **정답 무음 정의** | (원본 `kind: "silence"` 구간을 열화 시간축으로 매핑) **∪** (`inserted_spans` 중 `kind: "silence"`) |
| 귀속 규칙 | 가설 문자의 **중앙 시각(midpoint)** 이 정답 무음 안에 있으면 그 문자를 무음 구간에 귀속. 문자 시각은 **알고리즘 C**로 파생합니다 (문자 타이밍 → 단어 타이밍 → `canonical_cue_text` 기준 cue 내 균등 배분, C0). 정답 무음이 열화(`to`) 시간축에 정의되므로, 이 판정도 **알고리즘 A의 A1과 같은 `to` 시간축**에서 합니다 — 알고리즘 A로 제외된 문자도 여기서는 그대로 평가 대상입니다. 경계는 `[start, end)` 반개구간 |

**지표 4종 — 반드시 함께 봅니다**

| 지표 | 정의 | 분모 | 방향 |
|---|---|---|---|
| 무음 환각률 | 정답 무음에 귀속된 정규화 문자 수 | **정답 무음 총 길이(분)** → chars/min | 0에 가깝게 |
| 환각 사건률 | 정답 무음과 겹치는 가설 cue 개수 | 정답 무음 총 길이(시간) → events/hour | 0 |
| 반복 루프율 | 정규화 후 동일한 줄이 창(window) 안에서 `k`회 이상 연속 | 전체 가설 cue 수 | 0 |
| **무음 오탐률** | 가설 cue가 전혀 겹치지 않는 정답 발화 구간의 길이 합 | **정답 발화 총 길이** | 낮게 |

> **마지막 항목이 균형추입니다.** 환각을 없애겠다고 VAD를 조이면 실제 발화를 버립니다.
> 환각률만 보고 개선을 선언하는 것을 **금지**합니다. 4종을 같은 표에 함께 싣습니다.

`k`와 window 크기는 미정 (U-19와 함께 확정).

### 4.5 다국어 / 언어 전환 *(원문 축 전용)*

> **원문 축 지표입니다** (§4 Y-1). 정답은 `language_spans[]`이며 이는 **원본 음성의 언어**입니다
> ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0). 번역 결과의 언어를 이 지표로 재지 않습니다.

| 항목 | 규정 |
|---|---|
| 필요 정답 | **`ReferenceBundle.language_spans[]`** (`switch_kind` 포함). **이것이 언어의 유일한 정답입니다** — `utterances[].language`·`reference_cues[].language`는 파생 편의 필드이며 정답으로 쓰지 않습니다 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0) |
| 미지원 | `supports_language_id: false` — 이 경우 아래 전부 미지원 |

**(a) 언어 식별 정확도**

| 항목 | 규정 |
|---|---|
| 단위 | 고정 격자 (제안: 100ms 프레임) |
| 범위 | **정답 발화 구간만.** 무음은 제외 (무음에 언어가 없음) |
| 분모 | 정답 발화 구간의 격자 수 |
| 계산 | 격자별 정답 언어 vs 가설 언어 일치율. 가설 쪽 언어의 단일 출처는 **`Transcript.language_spans`** 하나이며([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0.2 L-1) **문자 오프셋** 기반이므로 아래 투영식으로 시간으로 옮깁니다. `SubtitleDocument` 가설에는 **적용하지 않습니다**(아래 D-02) |
| 보고 | 언어별 혼동 행렬 |

**지금 계산할 수 있는 것과 없는 것을 나눕니다 (REVIEW-025 D-03)**

| 범위 | 상태 | 근거 |
|---|---|---|
| **segment 단위** 언어 귀속 — 한 ASR segment의 text 전체가 **알려진 한 언어**로 덮일 때 그 segment 구간 `[start_seconds, end_seconds)` 전체를 그 언어로 본다 | **지원** | segment 구간은 계약이 보장하고, 그 안에 언어 경계가 없다 |
| segment 안에 **여러 language span**이 있을 때의 문자→시간 투영 (intra-segment 언어 구간·전환 시점) | **미지원** | 아래 |
| `SubtitleDocument` cue의 문자 범위 언어 | **미지원** | 아래 D-02 |

```
S1. Transcript segment의 language_spans가 gap·und 없이 **단일 known language**로
    text 전체를 덮으면, 그 segment 구간 전체의 가설 언어는 그 언어다.
S2. 격자 g의 가설 언어 = g의 중앙 시각을 포함하는 segment 구간의 언어.
    포함하는 구간이 없으면 "unknown".
S3. 그 조건을 만족하지 않는 segment(여러 언어·gap·und)는 이 지표의 분모에서
    **제외하고 그 사실을 보고**한다. 추정으로 채우지 않는다.
```

**segment 안쪽 문자→시간 투영은 아직 계약이 없습니다.**

- `Transcript`의 `tokens[]`는 **선택 필드**이고 `text`만 가질 뿐 **문자 오프셋이 없습니다.**
  token 문자열이 segment `text`를 정확히 한 번 분할한다는 계약도 없습니다.
- 따라서 "각 문자에 시각을 부여한다"는 규칙을 일반적으로 실행할 수 없습니다.
- cue 구간 균등 배분(알고리즘 C)을 여기에 끌어오면 **U-19(`norm-v1`)와 균등 배분 가정을
  이 TASK에서 임의로 확정**하는 셈이 됩니다. 그렇게 하지 않습니다.
- 명시적 문자↔시간 mapping(예: forced alignment 산출물, 또는 token에 문자 오프셋을 더하는
  후속 계약)이 생기면 그때 intra-segment 지표를 정의합니다. **오너 결정 항목입니다.**

`c_end ≤ c_start`인 빈 span은 어떤 경우에도 투영하지 않고 그 사실을 보고합니다.

| 가설 산출물 | 언어 구간을 어디서 얻나 | 시간 귀속 |
|---|---|---|
| `Transcript/v1` (원문 축) | 문서에 저장된 `segments[].language_spans[]` | **segment 단위만** (S1–S3). intra-segment는 미지원 |
| `SubtitleDocument/v1` | **없음 — 이 지표는 미지원입니다** (아래) | — |

**cue 문자 범위 LID는 현재 계약으로 계산할 수 없습니다 (REVIEW-024 D-02)**

`SubtitleDocument`에는 `language_spans`도 `dominant_language`도 없고
([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.0.2 L-2), 계보를 따라 **결정적으로 투영할 수도
없습니다.** 없는 대응을 있다고 쓰지 않기 위해 이 지표를 `SubtitleDocument` 가설에서
**미지원**으로 둡니다.

계산할 수 없는 이유는 다음과 같습니다.

- target 축 cue의 `lineage_fragments[]`는 `TranslatedTranscript.target_text`의 scalar 범위만
  가리킵니다. 원문 범위가 아닙니다.
- 번역 segment의 `source_fragments[]`는 **그 segment 전체**의 원문 범위를 줍니다.
  target 문자와 source 문자 사이의 정렬은 계약에 없습니다.
- 그래서 merged·split·어순이 바뀐 번역에서 특정 한국어 cue 조각을 특정 원문 language span에
  배정할 방법이 없습니다.
- `Transcript`의 token은 **선택 필드이고 문자 오프셋이 없습니다.** 문자 단위 LID를 시간으로
  옮기는 일반 규칙이 없습니다.
- 원문 축 cue도 `norm-v1`이 **U-19로 미정**이라 정규화 전후 offset mapping이 확정되지
  않았습니다. 이 TASK에서 U-19를 임의로 정하지 않습니다.

**대신 지금 보장하는 것은 segment 수준 추적 가능성입니다.** cue → 입력 segment ID →
(번역이면) `source_fragments[].source_segment_id` → 원문 Transcript segment까지 ID로
추적되고, 그 segment의 `language_spans`는 그대로 읽을 수 있습니다. 다만 그것을 cue의
**문자 범위**에 배정하지 않습니다.

명시적 source↔target 문자 정렬과 문자↔시간 매핑을 정의하는 후속 TASK가 생기면 그때
이 지표를 `SubtitleDocument` 가설로 확장합니다. 그 전에는 **원문 축 `Transcript` 가설**에만
적용합니다.

`lines[]` 결합에 넣는 **U+0020 구분자는 표시 문자열을 만들기 위한 인공 구분자이며 upstream 원문
증거가 아닙니다.** cue의 원문 계보는 `lineage_fragments[]`의 exact scalar 범위가 담습니다
([`ARCHITECTURE.md`](ARCHITECTURE.md) §7.4·§7.12). `norm-v1`의 내용은 **U-19로 미정**이며
TASK-029의 validator는 정규화 규칙을 새로 만들지 않습니다.

**(b) 전환 지점 탐지**

> **가설 쪽 전환 시점은 현재 계약으로 만들 수 없습니다** (REVIEW-025 D-03).
> 전환점은 segment 안쪽의 **문자 경계**이고, 그 경계를 시각으로 옮기려면 위 (a)가 미지원으로
> 둔 문자↔시간 mapping이 필요합니다. segment **사이**의 언어 변화는 segment 경계 시각으로
> 볼 수 있지만, 그것은 문장 내 전환이 아닙니다.
> 따라서 (b)와 (c)는 **명시적 문자↔시간 mapping 계약이 생기기 전까지 미지원**이며,
> 아래 규정은 그 계약이 생겼을 때 쓸 정의로 보존합니다. U-19나 균등 배분을 이 TASK에서
> 임의로 확정하지 않습니다.

| 항목 | 규정 |
|---|---|
| 매칭 | 정답 전환점과 가설 전환점을 **허용창 ±`T_sw`** 안에서 1:1 최근접 매칭 |
| 보고 | precision / recall / F1 + 매칭된 전환점의 절대 오차 중앙값 |
| 분모 | recall → 정답 전환점 수 / precision → 가설 전환점 수 |
| 주의 | `T_sw`를 크게 잡으면 점수가 좋아집니다. **리포트에 반드시 표기** (기본 제안 0.5초, U-18) |

**(c) 문장 내 전환 (intra-sentential)**

- 정답 `switch_kind: "intra_sentential"` 인 전환점만 골라 (b)를 재계산
- `supports_intra_sentential_lid: false`인 어댑터는 **미지원**
- **가장 어려운 항목입니다.** 전체 평균에 섞지 말고 따로 보고합니다

**(d) 스크립트 오염률**

- 정답 언어의 문자 체계와 다른 문자 체계로 표기된 정답-발화 격자 비율
- 분모: 정답 발화 격자 수

### 4.6 자막 형식 — 정답 불필요

정답 없이 계산 가능하므로 **실제 채점 입력에서도 측정할 수 있습니다** (신호 S6).

| 지표 | 계산 | 분모 |
|---|---|---|

| 줄 수 초과율 | `max_lines` 초과 cue 비율 | 전체 cue |

| 시간 겹침 오류율 | 같은 `stream_id` 안에서 cue 시간이 겹침 (형식 오류) | 전체 cue |
| 미표현 기능 비율 | `unsupported_features`로 버려진 정보가 있는 cue 비율 | 전체 cue |

- 임계값은 **언어별로 다릅니다** (`style_profile.language_overrides`). 구체 수치 미정 (U-18).
- **다른 `stream_id`끼리의 시간 겹침은 오류가 아닙니다** (동시 발화의 정상 표현).
- 이 절은 **축과 무관**하게 계산할 수 있습니다. 어느 축의 자막을 쟀는지 **표기**합니다 (§4 Y-5).

## 5. 시각 도메인 지표 (Phase 2)

> **전제:** 어떤 지표도 "원본을 복구했다"를 증명하지 않습니다.
> 지표는 **추정치가 얼마나 그럴듯한가**를 잴 뿐입니다 (`AGENTS.md` §1).

### 5.1 열화 영역 탐지 지표 — 재구성보다 먼저

**어디가 망가졌는지 못 찾으면 나머지는 의미가 없습니다.** 그런데 이전 판에는 탐지 지표가 없었습니다.

| 항목 | 규정 |
|---|---|
| 필요 정답 | `degradation_masks[].mask` (`RegionMask/v1`) — 종류 정확도는 추가로 **`degradation_masks[].degradation_kind`** ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3, §3.3) |
| 단위 | 픽셀 × 프레임 (고정 샘플링 레이트, 리포트에 명시) |
| 지표 | 픽셀 IoU, precision, recall, F1 |
| 영역 매칭 | 정답 영역과 예측 영역의 대응은 **알고리즘 B(전역 1:1 최적 할당)** 로 구합니다. greedy 금지, 동점 처리는 B의 tie-break 표 |
| 영역 단위 | 매칭된 정답 영역별 IoU ≥ 0.5 달성 비율 (region-level detection rate) |
| **종류 정확도** | **정답 축 = `degradation_masks[].degradation_kind`**, 가설 축 = `DegradedRegion/v1.degradation_kind` (§7.5). 알고리즘 B로 매칭된 쌍에 대해서만 혼동 행렬을 만듭니다. 두 축의 **허용값 집합은 동일**합니다 (`blur`·`mosaic`·`low_resolution`·`compression`·`sensor_noise`·`unknown`) |
| 시간 안정성 | 프레임별 마스크 IoU의 표준편차 (탐지가 깜빡이는가) |
| 분모 | recall → 정답 마스크 픽셀 수 / precision → 예측 마스크 픽셀 수 / **종류 정확도 → 매칭된 쌍 중 정답이 `unknown`이 아닌 쌍의 수** |
| 미지원 | `degradation_masks` 없는 실제 입력 (§3.1에 따라 "미지원"으로 보고) |

**이동 영역 주의:** `interpolation: "none"` 구간은 정답이 정의되지 않으므로 **분모에서 제외**합니다.

**종류 정확도의 전제 (REVIEW-002 M-05)**

- 합성 열화를 만들 때 **`recipe_id`와 `degradation_kind`를 함께 기록**합니다 (§3.2 레시피 표).
  둘의 대응이 어긋나면 **계약 검증 실패**이며 그 번들은 평가에 투입하지 않습니다
  ([`ARCHITECTURE.md`](ARCHITECTURE.md) §3.3).
- 정답이 `unknown`인 항목은 **종류 정확도의 분모에서 제외**합니다. 탐지 지표(IoU·precision·recall)에는
  그대로 포함합니다. "모른다"를 정답으로 채점하지 않습니다.
- **새 종류를 임의로 만들지 않습니다.** 값 집합을 늘리려면 양쪽 계약을 함께 바꾸고 major를 올립니다.

### 5.3 깨끗한 영역 보호 지표 — 부작용 탐지

**재구성이 손대지 않아야 할 곳을 바꾸는 것은 명백한 회귀입니다.**

| 지표 | 정의 | 게이트 |
|---|---|---|

| 허위 탐지율 | 정답 마스크 밖인데 탐지된 영역 비율 (§5.1 precision의 보수) | 보고 |

### 5.4 시간적 일관성 — **자명한 해(trivial solution) 방어 포함**

프레임 단위로는 좋아 보여도 재생하면 떨리는 것이 재구성의 전형적 실패입니다.
그런데 **일관성 지표만 보면 "전체를 흐리게" 또는 "프레임을 정지"시키는 것이 최고점**을 받습니다.
따라서 일관성 지표는 **항상 방어 지표와 함께** 보고합니다.

| 일관성 지표 | 정의 |
|---|---|
| 워핑 오차 (warping error) | 광학 흐름으로 이웃 프레임 정렬 후 차이 |
| 깜빡임 지수 (flicker index) | 정지 영역의 시간축 밝기·색 분산 |
| 경계 흔들림 | 재구성 경계의 시간축 변동 |
| 시간축 LPIPS 변화율 | 프레임 간 지각 거리의 급변 |

**방어 지표 (guard metrics) — 하나라도 위반하면 일관성 개선을 인정하지 않습니다**

#### 측정 범위 — **전체 프레임이 아니라 열화 영역 내부입니다**

이전 판은 측정 범위를 지정하지 않아, **영역 국소 자명해가 그대로 통과**했습니다 (REVIEW-002 M-07).
열화 영역이 화면의 5%일 때 "마스크 내부만 균일하게 흐리게" 하는 해법은 전역 고주파 에너지를
거의 낮추지 않으므로 전역 G1을 통과합니다. 따라서 **범위를 마스크 내부로 고정**합니다.

| 규칙 | 내용 |
|---|---|
| **R-S1** | **전체 프레임 값만으로 G1–G4를 판정하지 않습니다.** 전역 값은 참고로만 함께 보고합니다 |
| **R-S2** | 판정은 **열화 영역 내부**에서 합니다. 영역은 아래 우선순위로 정합니다 |
| **R-S3** | `clean_video`가 없는 **실제 입력에서도** 마스크 내부 무참조 선명도(§5.5)와 시간 일관성 검사를 적용합니다. full-reference 지표가 없다고 방어가 사라지지 않습니다 |
| **R-S4** | 마스크 내부 국소 흐림이 **전역 평균에 묻혀 통과하지 않도록**, 판정은 영역별로 하고 **하나라도 위반하면 전체 실패**로 집계합니다 |

**측정 영역의 우선순위**

```
S1. ReferenceBundle.degradation_masks[].mask 가 있으면 그것을 쓴다.   (합성 열화)
S2. 없으면 DegradedRegion/v1.mask (검출된 열화 마스크)를 쓴다.        (실제 입력)
S3. 둘 다 없으면 G1–G4를 "미지원"으로 보고한다.
    전역 값으로 대체해 통과시키지 않는다.
```

- 마스크 경계의 재구성 이음매가 값을 흔들 수 있으므로, 측정 전 마스크를 **안쪽으로 침식(erosion)** 합니다.
  침식 폭과 최소 픽셀 수는 **U-30** 미결정입니다.
- 각 지표는 **영역별로 계산하고, 영역 단위 결과를 모두 보고**합니다. 평균 하나로 접지 않습니다.

#### G1–G4

| # | 방어 | 무엇을 막는가 | 측정 범위 | 규칙 |
|---|---|---|---|---|
| G1 | 선명도 하한 | **"전부 흐리게" / 영역만 흐리게** 해법 | **마스크 내부** (S1→S2) | 마스크 내부 고주파 에너지 / 무참조 선명도 추정치가 **같은 마스크 내부의 입력(열화본) 수준 미만이면 실패**. `clean_video` 불필요 → 실입력에도 적용 |
| G2 | 움직임 보존 | **"프레임 정지" 해법** | **마스크 내부** | 마스크 내부의 프레임 간 변화량이 하한 미만이면 실패. 비교 기준은 `clean_video`가 있으면 정답, 없으면 입력 |
| G3 | 중복 프레임 비율 | 프레임 복제로 깜빡임 제거 | **마스크 내부** (전역도 함께 보고) | 마스크 내부가 이전 프레임과 사실상 동일한 프레임의 비율이 입력 대비 **유의하게 증가하면 실패** |
| G4 | 시간축 과평활 | 모션 블러로 뭉개기 | **마스크 내부** | 마스크 내부 광학 흐름 크기 분포 / 유효 해상도가 기준 대비 **축소되면 실패** |

**임계값과 판정 기준은 U-30입니다 — 추측으로 채우지 않습니다**

G1–G4의 "하한", "유의하게 증가", "축소"에 해당하는 **숫자와 유의성 판정 기준은 전부 미결정**이며
[`DECISIONS.md`](DECISIONS.md) §4.2의 **U-30**에 등록되어 있습니다 (R5).

- **측정 범위와 알고리즘은 위에 정의되어 있습니다.** U-30은 **숫자만** 남은 것입니다.
- 임계값이 정해지기 전에는 각 지표를 **"임계값 미정"** 으로 보고합니다.
  "미지원"이 아니며, 값 자체는 계산해 기록합니다.
- **임계값이 없다는 이유로 방어 지표를 생략하거나 통과 처리하지 않습니다.**

> **G1·G2 없이 보고된 시간적 일관성 수치는 해석하지 않습니다.**
> **전역 값만으로 보고된 G1–G4도 해석하지 않습니다** (R-S1).

### 5.6 인공물·환각 탐지

**재구성의 가장 위험한 실패는 "그럴듯한 거짓"입니다.**

| 검사 | 방법 | 무엇을 잡는가 |
|---|---|---|
| 구조 이탈 | 재구성 전후 저주파 구조 비교 | 형태 자체가 바뀜 |
| 텍스트 영역 | 화면 내 글자 영역의 판독 결과 비교 | **없던 글자 생성** — 가장 위험 |
| 얼굴 영역 | 정체성 특징의 프레임 간 변동 | 다른 사람처럼 보이게 됨 |
| 고주파 급증 | 추가된 디테일의 양 | 과도한 디테일 발명 |
| 색 이탈 | 주변 대비 색분포 이상 | 부자연스러운 색 |
| 경계 불연속 | 재구성 경계의 급변 | 붙인 티 |

**정책:** 인공물 신호가 임계를 넘으면 `artifact_flags`를 붙이고 사용자에게 **명시적으로 알립니다.**
조용히 내보내지 않습니다. 임계값 미정 (U-20).

> **정보 이론적 사실:** mosaic로 삭제된 정보는 존재하지 않습니다.
> "선명해 보인다"는 것은 정보를 되찾았다는 뜻이 아니라 **모델이 그럴듯한 값을 채워 넣었다**는 뜻입니다.
> 지표는 이 구분을 하지 못합니다. 그래서 §6이 필수입니다.

## 6. 사람 검토 — 무작위·계층·blind A/B

**이전 판의 "대표 구간 3개를 골라서 본다"는 방식은 체리피킹이 가능했습니다.**
만든 사람이 좋아 보이는 구간을 고르면 검토가 무의미해집니다. 다음 절차로 바꿉니다.

### 6.1 표본 추출 (사람이 고르지 않음)

1. 표본 단위는 **고정 길이 클립**입니다 (예: 5초, 리포트에 명시).
2. **계층(strata)** 을 먼저 정의합니다: `열화 종류 × 강도 × 출처 유형`.
3. 각 계층에서 **고정 시드 무작위 추출**합니다. 사람이 구간을 지정하지 않습니다.
4. 계층별 최소 표본 수를 사전에 정합니다 (U-26).
5. 추출 결과(시드·클립 목록)를 **먼저 기록한 뒤** 검토를 시작합니다. 추출 후 교체 금지.

### 6.2 제시 (blind A/B)

- 각 클립을 **A/B 두 버전**으로 제시합니다 (예: baseline vs 후보, 또는 입력 vs 출력).
- **좌우 배치를 무작위화**하고, 어느 쪽이 무엇인지 검토자에게 알리지 않습니다.
- 클립 제시 **순서도 무작위화**합니다.
- 검토자는 강제 선택 + 확신도를 기록합니다: `A 우세 / B 우세 / 구분 불가` + `확신 1–5`.

### 6.3 판정 규칙

| 항목 | 규칙 |
|---|---|
| 집계 | 계층별 승률 + 전체 승률, 신뢰구간과 함께 (§7) |
| 하한 | 전체 승률의 신뢰구간 하한이 50%를 넘어야 "개선" |
| 거부권 | 특정 계층에서 유의하게 나빠지면, 전체가 좋아도 **개선으로 인정하지 않음** |
| 검토자 편향 | 가능하면 만든 사람이 아닌 사람이 검토. 불가능하면 blind 절차를 반드시 유지하고 그 한계를 기록 |
| 복수 검토자 | 있으면 일치도(agreement)를 함께 보고 |

### 6.4 별도 항목: 인공물 자유 서술

승패와 별개로 **"원본에 없을 것 같은 요소를 봤는가"** 를 서술로 남깁니다.
승률이 좋아도 환각이 보고되면 §5.6 임계값을 재검토합니다.

기록 위치: `evals/<split>/<run_id>/human_review.md`
검토 주기·담당은 미정 (U-21).

## 7. 통계 처리 — 불확실성과 최소 실질 효과

**"좋아졌다"를 점 추정치 두 개의 대소로 판단하지 않습니다.**

### 7.1 짝지은 비교 (paired comparison)

- 같은 표본에 baseline과 후보를 모두 실행하고 **표본별 차이**를 봅니다.
- 군집 단위는 **출처(source)** 입니다 (§2.3). 같은 출처의 조각은 함께 재표본합니다.
- 신뢰구간은 **군집 부트스트랩(cluster bootstrap)** 으로 계산합니다. 반복 횟수는 리포트에 명시.
- 보고 형식: `Δ = -2.1 CER points, 95% CI [-3.4, -0.8], n_sources = 24`

### 7.2 시드 변동

- 최소 **3개 이상의 시드**로 실행하고 시드 간 분산을 보고합니다.
- 시드 하나의 차이가 시드 간 분산보다 작으면 **변화 없음**으로 봅니다.

### 7.3 최소 실질 효과 (minimum practical effect)

**통계적으로 유의해도 실질적으로 무의미한 차이가 있습니다.**

| 규칙 |
|---|
| 지표별 **최소 실질 효과 크기**를 사전에 정합니다 (U-27) |
| 개선 선언 조건: ① 신뢰구간이 0을 포함하지 않음 **그리고** ② 효과 크기 ≥ 최소 실질 효과 |
| 두 조건 중 하나라도 실패하면 `변화 없음`으로 기록합니다 |
| 최소 효과 크기를 **사후에 낮추지 않습니다** |

### 7.4 다중 비교

- 계층별로 여러 지표를 동시에 보면 우연한 "유의미"가 나옵니다.
- 1차 판단 지표(primary metric)를 **사전에 하나 지정**하고, 나머지는 보조로 취급합니다.
- 보조 지표에서만 나온 개선은 **가설**로 기록하고, 다음 실행에서 재확인합니다.

## 8. 평가 실행 규칙

1. **하나씩 바꾼다.** 여러 변경을 한 번에 넣으면 무엇이 효과였는지 알 수 없습니다.
2. **기준선을 먼저 만든다.** 첫 실행이 baseline입니다.
3. **같은 `dataset_id`·같은 `norm-v1` 버전끼리만 비교한다.**
4. **악화도 기록한다.** 실패한 시도를 지우면 같은 실수를 반복합니다.
5. **dev에서 반복하고, frozen-test는 아껴 쓴다** (§2.1).
6. **강도별 곡선을 본다.** 평균 하나로 판단하지 않습니다.
7. **미지원 지표를 0이나 결측 평균으로 채우지 않는다.** `status: "unsupported"`로 남깁니다.

## 9. 평가 우선순위 (자원이 부족할 때)

```
1. 무음 환각률 + 무음 오탐률          ← 가장 크게 점수를 깎는 실패 모드
2. 정규화 CER/WER                     ← 기본 정확도
3. 타임스탬프 정렬 (오차+누락+허위)   ← 3종 세트로만 의미 있음
4. 자막 형식 검사                     ← 정답 불필요, 자동화 쉬움, 실입력에서도 측정 가능
5. 번역 chrF2 + blind paired review     ← 채점 대상 축, 자동 점수 단독 승격 금지
6. 언어 식별 정확도                   ← 다국어 입력의 전제
7. 열화 영역 탐지 (§5.1)              ← 시각 도메인의 전제
8. 겹침 지표 (cpWER 또는 완화 지표)   ← 어렵고 개선도 어려움
9. 재구성 품질·일관성 지표 전체        ← Phase 2
```

> 순서는 **구현 난이도 대비 정보량** 기준입니다. 과제가 자막과 시각 재구성을
> **모두 요구**하므로 (`PRODUCT_SPEC.md` §2), 7·9를 영구히 미루는 것은 선택지가 아닙니다.

## 10. 채점 입력에 대한 정직한 입장

우리는 채점 입력의 정답을 **모릅니다.** 알 방법도 없습니다.

말할 수 있는 것:

- ✅ "합성 열화 P-HARD 조건에서 CER이 baseline 대비 유의하게 낮아졌다 (CI 포함)"
- ✅ "무음 구간 환각이 측정 가능하게 줄었고, 무음 오탐률은 악화되지 않았다"
- ✅ "dev 세트에서 개선이 관측되었고, blind 검토에서도 같은 방향이었다"

말할 수 **없는** 것:

- ❌ "채점에서 좋은 점수를 받을 것이다"
- ❌ "정답 자막과 거의 같다"
- ❌ "원본 영상을 복원했다"

**이 구분을 문서·UI·PR 설명 전부에서 유지합니다.**

## 11. 검증 위협 (Threats to Validity)

| 위협 | 내용 | 완화 |
|---|---|---|
| 분포 불일치 | 합성 열화가 실제 채점 입력과 다름 | 레시피 다양화, 강도 확대, **S2~S6 병용** (§1.1) |
| 지표 과적합 | 우리 지표만 좋아지는 변경을 채택 | 지표 다축 분리, 종합 점수 금지, 방어 지표(§5.4), frozen-test |
| 데이터 누출 | 같은 출처가 dev와 test에 분산 | 출처·화자·장면 단위 분할 (§2.2) |
| test 오염 | frozen-test를 반복 조회하며 튜닝 | 접근 기록, 조정 시 dev로 강등 (§2.1) |
| 표본 부족 | 적은 표본의 우연을 개선으로 오인 | `n` 필수 보고, 신뢰구간, 최소 실질 효과 (§7) |
| 자명한 해 | 흐리게/정지시켜 일관성 점수 획득 | 방어 지표 G1–G4 (§5.4) |
| 체리피킹 | 좋아 보이는 구간만 사람에게 보여줌 | 무작위·계층 추출, blind A/B (§6) |
| seed 코퍼스 편향 | 특정 언어·화자·환경에 치우침 | 다양성 요구(§2.6), 계층 보고(§2.4) |
| 정답의 불확실성 | seed 정답 자체에 오류 | 정답 검수 절차 필요 (U-06 조사에 포함) |
| 무참조의 기만성 | 지어낸 디테일이 점수를 올림 | §5.6 + §6 병행 |
| 평가자 편향 | 만든 사람이 후하게 봄 | blind 절차, 리뷰어 에이전트 분리 (`AGENTS.md` §3) |
| 미지원 지표의 은폐 | 계산 못 한 것을 평균에 섞음 | `status: "unsupported"` 명시 (§8 규칙 7) |

**가장 큰 위협은 첫 번째입니다.** 채점 원본이 비공개인 한 완전히 없앨 수 없습니다.
**줄이는 방법은 신호를 여럿 쓰는 것뿐입니다.**
