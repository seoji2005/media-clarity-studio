# EVALS.md — 평가 설계

**"좋아졌는가"를 채점 원본 없이 판단하는 방법.**

마지막 갱신: 2026-08-09 (Phase 0)
상태: **제안됨 (Proposed)** — 전략은 합의 필요, 임계값은 전부 미정

---

## 1. 근본 제약

> **채점용 원본 자막과 원본 영상은 채점자만 가지고 있습니다.**
> 우리는 점수를 볼 수 없고, 따라서 **채점 결과로부터 학습하거나 튜닝할 수 없습니다.**

이 제약의 결과:

| 못 하는 것 | 대신 하는 것 |
|---|---|
| 실제 정답과 직접 비교 | **우리가 정답을 아는 데이터를 만들어서** 비교 |
| 채점 점수로 하이퍼파라미터 조정 | 합성 열화 세트 점수로 조정 |
| 리더보드 순위로 개선 확인 | 조건별 품질 저하 곡선으로 확인 |
| 제출 결과 보고 재시도 | 제출 전에 우리 기준으로 확신 확보 |

**따라서 평가 하네스가 기능보다 먼저 만들어져야 합니다** ([`../PLAN.md`](../PLAN.md) Phase 1a).
측정 도구 없이 만든 개선은 개선인지 알 수 없습니다.

> **경고 (검증 위협):** 채점 피드백이 없다는 것은, 우리 지표에 과적합(overfit)할 위험이
> 항상 있다는 뜻이기도 합니다. §9에서 이 위험을 정면으로 다룹니다.

## 2. 합성 열화 전략 (Synthetic Degradation)

### 2.1 기본 아이디어

```
깨끗한 원본 + 확정된 정답
        │
        ├─► 열화 레시피 적용 (강도 조절 가능, 시드 고정)
        │           │
        │           ▼
        │      어려운 입력  ──► 우리 파이프라인 ──► 결과
        │                                            │
        └──────────── 비교 ◄─────────────────────────┘
                       │
                       ▼
              지표 + 품질 저하 곡선
```

**핵심:** 우리가 열화를 **직접 만들었기 때문에 정답을 압니다.**
채점 입력의 정답은 모르지만, 우리 입력의 정답은 압니다.
채점 입력이 우리 열화 세트와 성질이 비슷하다면, 우리 점수는 유용한 대리 지표가 됩니다.

### 2.2 seed 코퍼스 요구사항

| 요구 | 이유 |
|---|---|
| 정답 전사가 확정적일 것 | 정답이 흔들리면 모든 지표가 무의미 |
| 여러 언어 포함 | 다국어 전환 평가에 필요 |
| 여러 화자·성별·연령 | 특정 음성에 과적합 방지 |
| 원래 깨끗할 것 | 열화를 우리가 통제해야 함 |
| 사용·재배포가 허용될 것 | 저작권 (`AGENTS.md` §8) |
| 영상 트랙 포함 (일부) | 시각 재구성 평가에 필요 |

**미해결 U-06:** seed 코퍼스를 어떻게 확보하는가.
공개 음성 데이터셋, 직접 녹음, 라이선스가 명확한 소재 등 선택지가 있으나
**Phase 0에서는 결정하지 않습니다.** 라이선스 확인이 필요하고, 이는 사람의 판단 사항입니다.

### 2.3 열화 레시피

각 레시피는 **강도(severity) 0(없음) ~ 5(극심)** 로 조절 가능해야 합니다.
강도별 측정이 있어야 "어디서부터 무너지는가"를 알 수 있습니다.

**오디오 레시피**

| ID | 이름 | 모사하는 문제 | 조절 축 |
|---|---|---|---|
| D-A1 | `stationary_noise` | 지속적 배경 잡음 | SNR (dB) |
| D-A2 | `burst_noise` | 갑작스러운 큰 소리 | 발생 빈도, 피크 크기 |
| D-A3 | `speaker_overlap` | 겹치는 발화 | 겹침 비율, 간섭 화자 크기 |
| D-A4 | `long_silence` | 긴 무음 삽입 | 무음 길이, 삽입 횟수 |
| D-A5 | `bandwidth_reduction` | 전화 수준 대역 | 컷오프 주파수 |
| D-A6 | `codec_artifact` | 저비트레이트 압축 | 비트레이트 |
| D-A7 | `reverb` | 울리는 공간 | 잔향 시간 |
| D-A8 | `clipping` | 과입력 왜곡 | 클리핑 비율 |
| D-A9 | `language_switch` | 다국어 전환 | 전환 횟수, 전환 지점 |
| D-A10 | `level_instability` | 음량 급변 | 변동 폭 |

**영상 레시피 (Phase 2)**

| ID | 이름 | 모사하는 문제 | 조절 축 |
|---|---|---|---|
| D-V1 | `gaussian_blur` | 초점 흐림 | 커널 크기 |
| D-V2 | `motion_blur` | 움직임 흐림 | 길이, 각도 |
| D-V3 | `mosaic` | 모자이크 처리 | 블록 크기, 영역 |
| D-V4 | `downscale_upscale` | 해상도 축소 후 복귀 | 축소 배율 |
| D-V5 | `compression_artifact` | 블록·링잉 노이즈 | 품질 파라미터 |
| D-V6 | `sensor_noise` | 저조도 노이즈 | 노이즈 세기 |
| D-V7 | `frame_degradation` | 프레임 드롭·중복 | 드롭 비율 |

**조합 레시피 (실전 유사)**

단일 열화만으로는 실제 입력을 대표하지 못합니다. 조합 프로파일을 정의합니다.

```
P-EASY    : D-A1(1) + D-A5(1)
P-MEDIUM  : D-A1(3) + D-A3(2) + D-A9(1) + D-A6(2)
P-HARD    : D-A1(4) + D-A2(3) + D-A3(4) + D-A4(3) + D-A9(3) + D-A6(4)
P-VISUAL  : D-V1(3) + D-V3(3) + D-V4(3) + D-V5(3)
```

> 위 프로파일의 구체 수치는 **예시이며 확정이 아닙니다.**
> 실제 채점 입력을 관찰한 뒤 조정해야 합니다 (미해결 U-17).

### 2.4 재현성 규칙

- 모든 열화는 **시드 고정**입니다. 같은 시드 → 같은 열화 입력.
- 생성된 세트는 `dataset_id`로 식별하고, 레시피와 시드를 함께 기록합니다.
- 레시피가 바뀌면 `dataset_id`가 바뀝니다. **다른 데이터셋의 점수를 비교하지 않습니다.**

## 3. 자막 평가 지표

### 3.1 텍스트 정확도

| 지표 | 측정 대상 | 주의 |
|---|---|---|
| WER (Word Error Rate) | 단어 오류율 | 언어에 따라 단어 경계 정의가 다름 |
| CER (Character Error Rate) | 문자 오류율 | 한국어·중국어·일본어에서 WER보다 안정적 |
| 정규화 후 WER/CER | 표기 차이 제거 후 | **정규화 규칙을 문서에 고정할 것** |
| 삭제/삽입/치환 분해 | 오류의 성격 | 삽입 급증 = 환각 신호 |

**정규화(normalization)가 중요합니다.** 대소문자, 문장부호, 숫자 표기("3" vs "three"),
띄어쓰기 규칙을 통일하지 않으면 점수가 실제 품질이 아니라 표기 관습을 잽니다.
정규화 규칙은 **한 곳에 정의하고 버전을 붙입니다.** 규칙이 바뀌면 과거 점수와 비교하지 않습니다.

### 3.2 겹치는 발화 (Overlapping Speech)

일반 WER은 겹침 상황에서 오해를 부릅니다. 두 화자의 말이 섞이면
"어느 쪽 기준의 오류인가"가 정의되지 않습니다.

| 지표 | 설명 |
|---|---|
| cpWER (concatenated minimum-permutation WER) | 화자 배치를 최적으로 맞춘 뒤의 WER |
| 겹침 비율별 WER 곡선 | D-A3 강도별 저하 정도 |
| 화자 귀속 정확도 | diarization 채택 시 (U-15 확정 후) |
| 겹침 구간 누락률 | 겹칠 때 아예 못 잡은 발화의 비율 |

**diarization을 Phase 1에 넣지 않기로 하면** cpWER 대신
"겹침 구간에서 두 발화 내용이 모두 어딘가에 나타났는가"를 재는 완화된 지표를 씁니다.

### 3.3 무음 구간 (Silence) — **최우선 지표**

긴 무음에서 없는 문장을 만들어내는 것은 현대 ASR의 대표적 실패 모드이며,
**정답과 가장 크게 벌어지는 원인**입니다.

| 지표 | 정의 | 목표 방향 |
|---|---|---|
| 무음 환각률 (silence hallucination rate) | 정답이 무음인 구간에서 생성된 자막 문자 수 / 무음 총 길이 | 0에 가깝게 |
| 환각 사건 수 | 무음 구간당 생성된 cue 개수 | 0 |
| 반복 루프 검출 | 같은 문장이 연속 반복되는 현상 | 0 |
| 무음 오탐 (false silence) | 실제 발화를 무음으로 버린 비율 | 낮게 |

**마지막 항목이 균형추입니다.** 환각을 없애겠다고 VAD를 과하게 조이면
실제 발화를 통째로 버립니다. 두 지표를 **항상 함께** 봅니다.

### 3.4 다국어 전환 (Multilingual / Code-switching)

| 지표 | 설명 |
|---|---|
| 언어 식별 정확도 | 구간별 언어 판정이 맞는 비율 |
| 전환 지점 탐지 오차 | 언어가 바뀐 시점과 탐지 시점의 차이(초) |
| 언어별 WER/CER | 특정 언어만 크게 나쁜지 확인 |
| 스크립트 오염률 | 잘못된 문자 체계로 표기된 비율 (예: 일본어 구간을 로마자로) |
| 문장 내 전환 처리 | 한 문장 안에서 언어가 바뀔 때의 처리 품질 |

**문장 내 전환(intra-sentential switching)이 가장 어렵습니다.**
구간 단위 언어 식별로는 다루기 어려우므로, 실패하면 별도 전략이 필요합니다 (U-13).

### 3.5 타임스탬프 정렬 (Timestamp Alignment)

자막은 **내용이 맞아도 시간이 틀리면 쓸모없습니다.**

| 지표 | 정의 |
|---|---|
| 시작 시각 절대 오차 | 평균 / 중앙값 / 95퍼센타일 (초) |
| 종료 시각 절대 오차 | 동일 |
| 구간 IoU | 정답 cue와 생성 cue의 시간 겹침 비율 |
| 드리프트 | 영상 후반으로 갈수록 오차가 커지는가 |
| 동기 이탈률 | 오차가 허용치(예: 0.5초)를 넘는 cue 비율 |

**드리프트를 따로 재는 이유:** 누적 오차는 초반만 보면 안 보입니다.
영상 앞·중간·뒤 구간을 나눠서 봐야 드러납니다.

### 3.6 자막 형식 (Subtitle Formatting)

내용·시간이 맞아도 읽기 어려우면 제품으로서 실패입니다.

| 지표 | 설명 |
|---|---|
| CPS (characters per second) | 읽기 속도. 초과 비율 측정 |
| 줄당 문자 수 초과율 | `style_profile.max_chars_per_line` 위반 |
| 줄 수 초과율 | 보통 2줄 초과 |
| 최소/최대 표시 시간 위반율 | 너무 짧거나 긴 cue |
| cue 간 최소 간격 위반율 | 깜빡임 유발 |
| 시간 겹침 오류 | cue끼리 시간이 겹침 (형식 오류) |
| 줄바꿈 품질 | 문법 단위를 부자연스럽게 끊었는가 |

CPS·줄 길이의 **구체 임계값은 미정**입니다. 언어별로 달라야 합니다 (미해결 U-18).

### 3.7 종합 판단

**단일 종합 점수를 만들지 않습니다.**

가중 평균 하나로 뭉치면 어느 축이 무너졌는지 안 보이고,
그 가중치 자체가 근거 없는 결정이 됩니다.
대신 **지표 카드(scorecard)** 로 나란히 봅니다.

```
Run: 2026-08-09-a   Dataset: synth-v1 (seed 1234)   Profile: P-HARD
─────────────────────────────────────────────────────────
CER (정규화)                 : __
무음 환각률                  : __      ← 최우선
무음 오탐률                  : __
겹침 구간 누락률             : __
언어 식별 정확도             : __
시작 시각 오차 (중앙값/p95)  : __ / __
형식 규칙 위반율             : __
─────────────────────────────────────────────────────────
이전 실행 대비: (개선/악화/변화없음) 축별 표시
```

## 4. 영상 재구성 평가 (Phase 2)

> **전제:** 어떤 지표도 "원본을 복구했다"를 증명하지 않습니다.
> 지표는 **추정치가 얼마나 그럴듯한가**를 잴 뿐입니다 (`AGENTS.md` §1).

### 4.1 객관 지표 — 원본을 아는 경우 (합성 열화)

우리가 열화를 만들었으므로 원본이 있습니다. Full-reference 지표를 쓸 수 있습니다.

| 지표 | 측정 성격 | 한계 |
|---|---|---|
| PSNR | 픽셀 차이 | 사람의 인지와 잘 안 맞음 |
| SSIM / MS-SSIM | 구조 유사도 | PSNR보다 낫지만 여전히 제한적 |
| LPIPS | 학습된 지각 유사도 | 사람 인지에 더 가까움 |
| DISTS | 텍스처·구조 균형 | 보조 |
| 영역 한정 지표 | 열화 영역만 따로 측정 | **전체 평균은 열화 영역의 실패를 희석시킴** |

**마지막 항목이 중요합니다.** 화면의 5%가 모자이크인데 전체 PSNR을 재면
아무것도 안 해도 점수가 높게 나옵니다. **반드시 영역 한정으로 측정합니다.**

### 4.2 객관 지표 — 원본이 없는 경우 (실제 입력)

채점 입력에는 원본이 없습니다. No-reference 지표만 가능합니다.

| 지표 | 측정 |
|---|---|
| NIQE / BRISQUE | 자연스러움 (학습 기반 무참조 화질) |
| 선명도 추정 | 경계 강도 분포 |
| 블록 아티팩트 지표 | 압축 격자 흔적 |
| 노이즈 추정 | 잔여 노이즈 |

> **무참조 지표는 속기 쉽습니다.** 과하게 선명하게 만들면 점수가 오르지만
> 실제로는 없던 디테일을 지어낸 것일 수 있습니다.
> **무참조 지표만으로 성공을 선언하지 않습니다.** 반드시 §4.4·§4.5와 함께 봅니다.

### 4.3 시간적 일관성 (Temporal Consistency)

프레임 단위로는 좋아 보여도 재생하면 떨리고 깜빡이는 것이 재구성의 전형적 실패입니다.

| 지표 | 설명 |
|---|---|
| 워핑 오차 (warping error) | 광학 흐름으로 이웃 프레임을 정렬한 뒤의 차이 |
| 깜빡임 지수 (flicker index) | 정지 영역의 시간축 밝기·색 분산 |
| 정체성 안정성 | 같은 대상이 프레임마다 다른 모습이 되는가 |
| 경계 흔들림 | 재구성 영역과 원본 영역의 경계가 떠는가 |
| 시간축 LPIPS 변화율 | 프레임 간 지각 거리의 급변 |

**단일 프레임 지표만으로는 절대 판단하지 않습니다.**

### 4.4 인공물·환각 탐지 (Artifact & Hallucination Detection)

**재구성의 가장 위험한 실패는 "그럴듯한 거짓"입니다.**
없던 얼굴, 없던 글자, 없던 무늬가 생기는 것.

| 검사 | 방법 | 무엇을 잡는가 |
|---|---|---|
| 구조 이탈 검사 | 재구성 전후 저주파 구조 비교 | 형태 자체가 바뀜 |
| 텍스트 영역 검사 | 화면 내 글자 영역의 판독 결과 비교 | **없던 글자 생성** — 가장 위험 |
| 얼굴 영역 검사 | 정체성 특징의 프레임 간 변동 | 다른 사람처럼 보이게 됨 |
| 고주파 급증 검사 | 추가된 디테일의 양 | 과도한 디테일 발명 |
| 색 이탈 검사 | 주변 대비 색분포 이상 | 부자연스러운 색 |
| 경계 불연속 검사 | 재구성 경계의 급변 | 붙인 티 |

**정책:** 인공물 신호가 임계를 넘으면 결과에 `artifact_flags`를 붙이고
사용자에게 **명시적으로 알립니다.** 조용히 내보내지 않습니다.

> **정보 이론적 사실:** mosaic로 삭제된 정보는 존재하지 않습니다.
> 재구성이 "선명해 보인다"는 것은 정보를 되찾았다는 뜻이 아니라
> **모델이 그럴듯한 값을 채워 넣었다**는 뜻입니다. 지표는 이 구분을 하지 못합니다.
> 그래서 §4.5(사람 검토)가 필수입니다.

### 4.5 사람 검토 (Human Review)

지표가 못 잡는 것을 사람이 봅니다. **선택이 아니라 필수 절차입니다.**

**검토 루브릭 (각 1–5점, 근거 문장 필수)**

| 항목 | 질문 |
|---|---|
| 자연스러움 | 처리한 티가 안 나는가 |
| 시간적 안정성 | 재생할 때 떨리거나 깜빡이지 않는가 |
| 내용 정합성 | 원본에 없을 것 같은 요소가 생기지 않았는가 |
| 개선 정도 | 처리 전보다 실제로 나은가 |
| 부작용 | 다른 부분이 나빠지지 않았는가 |

**절차 규칙**

- 최소 3개 대표 구간, 각 5초 이상
- 가능하면 **어느 쪽이 처리 결과인지 모르는 상태(blind)** 로 비교
- "개선 정도"가 3점 미만이면 지표가 좋아도 **개선으로 인정하지 않습니다**
- 검토 결과는 `evals/<run_id>/human_review.md`에 기록

## 5. 평가 실행 규칙

1. **하나씩 바꾼다.** 여러 변경을 한 번에 넣으면 무엇이 효과였는지 알 수 없습니다.
2. **기준선을 먼저 만든다.** 첫 실행이 baseline입니다. 이후 전부 이것과 비교합니다.
3. **같은 데이터셋끼리만 비교한다.** `dataset_id`가 다르면 비교하지 않습니다.
4. **악화도 기록한다.** 실패한 시도를 지우면 같은 실수를 반복합니다.
5. **시드를 여러 개 쓴다.** 시드 하나의 결과는 우연일 수 있습니다.
6. **강도별로 본다.** 평균 하나가 아니라 severity 0–5 곡선을 봅니다.

**리포트 저장 위치**

```
evals/<run_id>/
├── report.json          # 기계 판독용
├── report.md            # 사람 판독용 (한국어)
├── manifest.json        # 설정·버전·시드·dataset_id
├── per_condition/       # 조건별 상세
└── human_review.md      # Phase 2 이후
```

## 7. 평가 우선순위 (자원이 부족할 때)

전부 만들 시간이 없다면 이 순서입니다.

```
1. 무음 환각률 + 무음 오탐률        ← 가장 크게 점수를 깎는 실패 모드
2. 정규화 CER/WER                   ← 기본 정확도
3. 타임스탬프 정렬 오차             ← 내용이 맞아도 시간이 틀리면 무의미
4. 언어 식별 정확도                 ← 다국어 입력의 전제
5. 자막 형식 검사                   ← 자동화가 쉽고 확실한 이득
6. 겹침 구간 지표                   ← 어렵고, 개선도 어려움
7. 영상 재구성 지표 전체            ← Phase 2
```

## 8. 채점 입력에 대한 정직한 입장

우리는 채점 입력의 정답을 **모릅니다.** 알 방법도 없습니다.

따라서 다음과 같이 말할 수 있습니다.

- ✅ "합성 열화 P-HARD 조건에서 CER이 이전 실행보다 낮아졌다"
- ✅ "무음 구간 환각이 측정 가능하게 줄었다"
- ✅ "이 변경은 우리 평가 세트에서 개선을 보였다"

다음과 같이 말할 수 **없습니다.**

- ❌ "채점에서 좋은 점수를 받을 것이다"
- ❌ "정답 자막과 거의 같다"
- ❌ "원본 영상을 복원했다"

**이 구분을 문서·UI·PR 설명 전부에서 유지합니다.**

## 9. 검증 위협 (Threats to Validity)

이 평가 설계가 틀릴 수 있는 지점을 스스로 적어 둡니다. 리뷰어는 여기부터 공격하십시오.

| 위협 | 내용 | 완화 |
|---|---|---|
| 분포 불일치 | 합성 열화가 실제 채점 입력과 다름 | 레시피 다양화, 강도 폭 확대, 조합 프로파일 |
| 지표 과적합 | 우리 지표만 좋아지는 변경을 채택 | 지표를 여러 축으로 분리, 종합 점수 금지, 사람 검토 |
| seed 코퍼스 편향 | 특정 언어·화자·녹음 환경에 치우침 | 다양성 요구사항(§2.2), 언어별 분리 보고 |
| 정답의 불확실성 | seed 정답 자체에 오류 | 정답 검수 절차 필요 (U-06과 함께 결정) |
| 무참조 지표의 기만성 | 지어낸 디테일이 점수를 올림 | §4.4 인공물 탐지 + §4.5 사람 검토 병행 |
| 시드 우연 | 한 시드의 결과를 일반화 | 다중 시드 (§5 규칙 5) |
| 평가자 편향 | 만든 사람이 검토하면 후하게 봄 | blind 비교, 리뷰어 에이전트 분리 (`AGENTS.md` §3) |

**가장 큰 위협은 첫 번째입니다.** 그리고 채점 원본이 비공개인 한
이것을 완전히 없앨 방법은 없습니다. 줄일 수만 있습니다.
