## 1. 승인됨 (Accepted)

---

### ADR-0001 — Phase 0에서는 코드를 쓰지 않는다 (문서 우선)

**맥락:** 요구사항이 불확실하고, 서로 대화를 볼 수 없는 여러 에이전트가 병렬 작업해야 함.
**결정:** Phase 0의 산출물은 문서뿐. 기능 코드·의존성·모델·CI·비밀정보를 추가하지 않는다.
**근거:** 공유 전제 없이 시작한 코드는 나중에 전부 버려야 함. 문서는 코드보다 고치기 싸다.
**되돌리기:** Phase 1 진입 시 자연스럽게 해제.

---

### ADR-0002 — "복원"이 아니라 "재구성/추정"으로 기술한다

**맥락:** mosaic·blur는 정보를 실제로 삭제한다. 원본은 알 수 없다.
**결정:** 모든 시각 개선 결과를 재구성(reconstruction) 또는 추정(estimation)으로 기술한다.
**결과:** `is_estimate`는 상수 true (ADR-0016). 모듈·어댑터 이름도 `reconstruct` 계열 (ADR-0026).
**되돌리기:** 없음.

---

### ADR-0003 — Local-first를 기본값으로 한다

**결정:** 네트워크 없이 동작하는 것이 기본. 클라우드 전송은 사용자가 켜는 선택 기능.
**결과:** `export`가 선택적 주변부가 된다 (Phase 4). 처리 성능은 사용자 PC에 달린다.

---

### ADR-0005 — 합성 열화를 **주된** 평가 신호로 쓴다 *(범위 정정됨)*

**맥락:** 채점 원본이 비공개라 실제 정답과 비교할 수 없다.
**결정:** 정답을 아는 데이터에 열화를 가해 dev 평가 세트를 만든다.
**정정 (REVIEW-001):** 이전 판은 이를 **"유일하게 신뢰 가능한 신호"** 라고 기술했다. 그것은 과한 주장이다.
합성 열화는 **주된 신호(primary dev signal)** 이며, 자연 실데이터·무참조 지표·사람 blind 검토·
교차 일치도·형식 검사와 **함께** 사용한다 ([`EVALS.md`](EVALS.md) §1.1).
**결과:** 개선 주장은 합성 신호 + 최소 하나의 다른 신호가 같은 방향일 때만 한다.

---

### ADR-0006 — 에이전트는 브랜치와 PR로만 협업한다

**결정:** TASK당 수행 소유자 1개 세션, 리뷰어는 **다른 Claude Code 세션**.
인계는 저장소 파일과 PR 설명으로만.
**근거:** 각 세션은 서로의 대화를 볼 수 없다. 저장소가 유일한 공유 매체다.
역할 구성은 ADR-0027에서 갱신되었다.

---

### ADR-0007 — 사람이 읽는 설명은 한국어, 식별자는 영어

**결정:** 산문은 한국어. 파일명·명령어·코드 식별자·정착된 기술 용어는 영어 유지.

---

### ADR-0008 — `AGENTS.md`가 규칙의 단일 출처다

**결정:** 규칙 충돌 시 `AGENTS.md`가 이긴다. **모든 에이전트의 문서 읽기 순서에서 첫 번째다.**
`CLAUDE.md`는 규칙을 복제하지 않고 참조만 한다.

---

### ADR-0009 — 에이전트는 병합하지 않는다. 사람 오너는 리뷰 후 병합한다 *(정정됨)*

**정정 (REVIEW-001):** 이전 판은 "`main`을 병합하지 않는다"를 주체 구분 없이 적어,
사람 오너의 병합까지 금지하는 것처럼 읽혔다.

**결정 (주체별로 명확히)**

| 주체 | `main` 직접 커밋/push | 병합 |
|---|---|---|
| AI 에이전트 (Claude Code 세션 전부, GPT Work) | **금지** | **금지** |
| 사람 제품 오너 | 가능하나 권장하지 않음 | **리뷰 후 병합 가능. 이것이 정상 경로** |

**근거:** 검토 없는 자동 병합을 막는 것이 목적이지, 오너의 병합을 막는 것이 아니다.

---

### ADR-0010 — 원본 입력 파일을 절대 수정하지 않는다

**결정:** 입력은 읽기 전용. 출력은 항상 새 파일. 덮어쓰기는 기본 동작이 아니다.

### ADR-0027 — 운영 구조를 네 역할로 전환한다 *(신규 — 오너 지시)*

**맥락:** 이전 운영은 Claude와 Codex 두 에이전트를 대칭적으로 두고, 독립 리뷰를
Codex(및 Codex Cloud / GitHub `@codex review`)가 맡는 것을 전제했다.
사람 제품 오너가 운영 구조를 바꾸기로 결정했다.

**결정 — 향후 운영은 다음 네 역할로 한다**

| # | 역할 | 책임 | 저장소 커밋 |
|---|---|---|---|
| 1 | **GPT Work** | 전체 오케스트레이션, 요구사항·우선순위 결정 지원, 작업 분해, Claude에 전달할 정확한 프롬프트 작성, 결과 비교와 오너의 최종 판단 지원 | 하지 않음 |
| 2 | **Claude Code Cloud 주 세션** | Lead Developer. 핵심 설계·구현, 복잡한 디버깅, 성능 최적화. TASK Owner | 함 |
| 3 | **독립 Claude Code 리뷰 세션** | Independent Reviewer. 작성자와 **다른 새 세션**, 작성자 대화 맥락 없음. 저장소·TASK·PR diff만 보고 검토. TASK Reviewer | 리뷰 문서만 |
| 4 | **Claude 일반 대화** | 아키텍처 자문, 기술 선택 비교, 막힌 문제의 두 번째 의견 | 하지 않음 |

**함께 결정한 제약**

1. **Codex / Codex Cloud / GitHub `@codex review`는 향후 역할·배정·절차에서 제거한다.**
2. **작성자와 리뷰어는 반드시 서로 다른 Claude Code 세션이다.** 주 세션은 자기 변경을
   스스로 최종 승인하지 않는다 (`AGENTS.md` R8 / §3.1).
3. **Claude 사용량이 제한적이므로** 주 세션은 고난도 구현에 집중하고,
   독립 리뷰는 **중요한 PR과 핵심 알고리즘 변경에만** 사용한다 (`AGENTS.md` §3.2).
4. **두 세션이 같은 파일을 동시에 수정하지 않는다** (`AGENTS.md` R9 / §3.4).
5. **완료 보고만 신뢰하지 않고**, 가능한 경우 GitHub 상태와 diff로 확인한다
   (`AGENTS.md` R10 / §3.5).
6. **AI는 병합하지 않는다.** 병합 결정은 사람 제품 오너만 한다 (ADR-0009 유지).
7. 리뷰어는 **리뷰 대상 브랜치의 파일을 직접 수정하지 않는다** (`AGENTS.md` §3.3).

**역사 기록의 취급**

- 과거에 실제로 수행된 기록 — REVIEW-001이 **Codex/GPT Work를 통해 전달**된 사실,
  TASK-000·TASK-001의 당시 Owner/Reviewer, 기존 커밋의 작성·검토 이력 — 은
  **사실이므로 삭제하거나 다른 주체가 한 것처럼 바꾸지 않는다.**
- 대신 **"완료된 역사 기록"임을 명시**하고, 미래 규칙과 구분한다.
- 과거 TASK 문서 안에 **미래 표준 절차로 남아 있던** Codex 지시·예시 브랜치·다음 리뷰
  지시는 제거하거나 현재 운영 구조로 교체한다.

**왜 "승인됨"인가:** 이 결정은 에이전트가 만든 전략이 아니라 **사람 제품 오너의 지시**다
(상태 표기 규칙 §상태 표기 참조). 근거는 오너 지시이며, 바꾸려면 오너 승인 + PR이 필요하다.

**기록:** [`tasks/TASK-007.md`](tasks/TASK-007.md)

### ADR-0004 — 자막을 먼저 착수한다 *(제안됨 — 이전 판의 "승인됨"에서 정정)*

**정정 (REVIEW-001):** 이전 판은 이 결정을 **승인됨**으로 표시하고,
근거로 "과제 채점 대상도 자막이 중심이다"라고 적었다.
**그 근거는 검증되지 않았다.** 배점 비중은 U-24로 미해결이다.

**결정 (범위를 좁혀 다시 진술)**

- 자막을 **먼저 착수**한다. 이것은 **순서 제안**이다.
- 근거는 "자막이 더 중요해서"가 아니라 **"평가 기반을 먼저 세우기 위해서"** 다.
  자막 단계에서 만드는 평가 하네스·`ReferenceBundle`·시간축 계약을 시각 도메인이 재사용한다.
- **범위 축소가 아니다.** 과제는 자막과 시각 재구성을 모두 요구한다
  ([`PRODUCT_SPEC.md`](PRODUCT_SPEC.md) §2, AS-1).

**금지되는 추론:** "Phase 2니까 급하면 버려도 된다."
일정 부족 시의 범위 조정은 **사람 오너의 결정**이다 (AS-4).

**반박 가능 지점:** 시각 재구성을 먼저 하거나 완전 병렬로 진행하는 것도 가능하다.
특히 U-24가 시각 비중이 크다고 밝혀지면 이 순서는 재검토되어야 한다.

**대안:** 필드를 없애고 타입 이름으로 표현. 구현 시 재검토 가능하나 **의미는 바뀌지 않는다.**

UI 전용 기능은 존재할 수 없다. 단, 안전 게이트 확인은 UI가 반드시 제시해야 한다 (ADR-0022).

### ADR-0018 — 재현성을 **세 등급으로 구분**한다 *(제안됨 — 이전 판 정정)*

**정정 (REVIEW-001):** 이전 판은 "manifest로 재현성을 보장한다"라고 적었다.
**그것은 사실이 아니다.** manifest는 무엇으로 만들었는지 기록할 뿐,
GPU 비결정 경로에서 동일 출력을 보장하지 않는다.

**결정**

| 등급 | 보증 |
|---|---|
| T1 비트 단위 결정성 | 바이트 단위로 동일한 출력 |
| T2 허용오차 내 반복성 | 정의된 허용오차 내 동일 |
| T3 출처 재현성 | **무엇으로 어떻게 만들었는지 기록됨. 출력 동일성은 보증하지 않음** |

- **manifest는 T3만 보증한다.**
- 비결정 경로가 있으면 T1을 주장하지 않고 `nondeterminism_sources`를 기록한다.
- 허용오차 수치는 **U-29** 미해결.

### ADR-0019 — 모델 라이선스·재배포 검토는 **모델 후보 선정 시점**에 한다 *(제안됨 — 이전 판의 "승인됨"에서 정정)*

**맥락:** 이전 판은 라이선스 검토를 가격 정책과 묶어 Phase 4로 미뤄 두었다.
**문제:** 재배포 불가 라이선스의 모델로 파이프라인을 만든 뒤 Phase 4에서 알게 되면,
그 시점에 파이프라인을 다시 만들어야 한다. 검토가 너무 늦다.

**결정**

| 항목 | 시점 |
|---|---|

### ADR-0021 — 공통 계약과 정준 시간축을 둔다 *(제안됨)*

**결정:** `ArtifactRef/v1`, `Timebase/v1`, `TimeMapping/v1`, `RegionMask/v1`.

| 단일 종합 품질 점수를 채점 예측으로 사용 | 채점 방식을 모른다. 예측이라 부를 수 없다 |
| "모자이크 완전 제거" 목표 | 원리적으로 불가능. ADR-0002 위반 |
| **배점 가정에 근거한 시각 재구성 폐기** | U-24가 미해결이다. 검증되지 않은 가정으로 필수 산출물을 버릴 수 없다 |
| **"채점 피드백이 없으니 학습이 불가능하다"는 논리** | **틀린 논리다.** 채점 신호가 없어도 학습은 원리적으로 가능하다. 학습을 미루는 실제 이유는 범위·데이터·연산·일정이다 ([`PRODUCT_SPEC.md`](PRODUCT_SPEC.md) §6.3) |
| **manifest만으로 동일 출력을 보장한다는 주장** | GPU 비결정 경로에서 성립하지 않는다 (ADR-0018) |
| **합성 열화를 "유일하게 신뢰 가능한 신호"로 규정** | 과한 주장이며 과적합을 유도한다 (ADR-0005) |

## 6. 결정을 추가하는 방법

1. 새 ADR 번호 부여 (재사용 금지)
2. **맥락 → 결정 → 근거 → 결과 → 되돌리기** 순으로 기록
3. 상태 라벨을 **반드시** 붙인다
4. 관련 문서에 반영하고 상호 링크
5. 상태가 바뀌면 **이전 내용을 지우지 말고** 변경 사실을 덧붙인다 (ADR-0004·0009·0018 참조)

**기각된 안도 기록합니다.** 왜 안 했는지 남기지 않으면 같은 논의를 반복하게 됩니다.
