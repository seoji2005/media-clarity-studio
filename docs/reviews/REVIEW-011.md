## 2. M-01 — SRT 바이트 규약과 재현성

### 2.1 판정: **부분 해소**

**REVIEW-010이 요구한 수정 조건 3개는 모두 충족됐고, 기록된 모든 수치가 실측으로 재현됐다.**
남은 것은 §7.1.1 자체 검사 블록의 숫자 1개 모순이다 (F-01).

### 2.2 직접 실행한 명령

§7.1.1의 `printf` 블록, §7.2의 `ffmpeg` 블록, §7.3의 probe/soft-sub/extract/비교 블록,
§7.3.1의 `srt-canon.sh` here-doc을 **문자 그대로** 복사해 깨끗한 `mktemp -d`에서 실행했다.

```bash
LC_ALL=C printf '%s\n' \
  '1' '00:00:00,500 --> 00:00:02,500' '[fixture cue 1]' '' \
  '2' '00:00:03,000 --> 00:00:05,500' '[fixture cue 2]' '' > fixture.srt
```

### 2.3 SRT 바이트 규약 — 기대값 대 실측값

| 규약 항목 | 문서 기대값 | 실측값 | 판정 |
|---|---|---|---|
| 인코딩 / BOM | UTF-8, BOM 없음 | `head -c 3` = `31 0a 30` (`ef bb bf` 아님) | **일치** |
| 줄바꿈 | LF만, CR 없음 | `grep -c $'\r'` = **0** | **일치** |
| trailing space·tab | 없음 | `grep -nP '[ \t]+$'` **출력 없음** | **일치** |
| 파일 끝 | 정확히 `0a 0a` | `tail -c 2 … od -An -tx1` 출력 = ` 0a 0a` | **일치** |
| 총 바이트 | **98 bytes** | `wc -c` = **98** | **일치** |
| SRT SHA-256 | `c2ed5960b423ee3d00c23d4d4f61dc62371fdb22e0fa090766bbb8262120eb97` | **동일** | **일치** |

전체 hexdump로 98 bytes 전부를 직접 확인했다. 마지막 2 byte가 `0a 0a`이고, 그 앞이
`... 63 75 65 20 32 5d`(`[fixture cue 2]`)임을 눈으로 대조했다.

**질문 1 — `printf` 명령 자체가 마지막 빈 줄까지 결정하는가: 예.**
`printf '%s\n'`는 각 인자 뒤에 정확히 `\n` 하나를 붙이므로, 마지막 인자 `''`가 EOF의 두 번째
`0a`를 만든다. 결과 바이트가 인자 목록으로 **완전히 결정**된다. 문서의 서술이 정확하다.

**질문 2 — 복사 실행만으로 정확히 98 bytes가 나오는가: 예.** 두 번의 독립 실행에서 모두 98.

### 2.4 두 번 생성 — 전체 SHA-256과 크기 (실측)

| 산출물 | RUN 1 SHA-256 | RUN 2 SHA-256 | 크기 | byte-identical |
|---|---|---|---|---|
| `fixture-source.mkv` | `3bd1180d5445839baf32643e7f78be15d4818c14f1d0152e79a57377919ce37b` | **동일** | **3,635,787 bytes** | **예** |
| `fixture.srt` | `c2ed5960b423ee3d00c23d4d4f61dc62371fdb22e0fa090766bbb8262120eb97` | **동일** | **98 bytes** | **예** |
| `fixture-softsub.mkv` | `2f2eb1ba73813133af5c311e3329c1bd5bf445f1192451397bb83af267a623ed` | **동일** | **3,636,043 bytes** | **예** |
| `fixture-extracted.srt` | `c2ed5960b423ee3d00c23d4d4f61dc62371fdb22e0fa090766bbb8262120eb97` | **동일** | 98 bytes | **예** |

**문서가 기록한 세 해시와 두 크기가 전부 실측과 일치한다.** 각 RUN은 서로 다른 임시 디렉터리에서
독립 실행했다.

**probe 실측:** `format_name=matroska,webm`, `duration=6.000000`, `probe_score=100`,
`size=3636043`, streams = `ffv1` 640×360 30/1 + `pcm_s16le` 48000 Hz mono + `subrip`.
문서 §7.4의 기술과 일치한다.

| 검사 | 결과 |
|---|---|
| 추출본 SHA-256 | `c2ed5960…` — **입력과 동일** |

### 2.6 canonical 비교

`srt-canon.sh` 출력(양쪽 동일):

```
CUE	1	00:00:00,500 --> 00:00:02,500	[fixture cue 1]
CUE	2	00:00:03,000 --> 00:00:05,500	[fixture cue 2]
```

**cue 번호·시작 시각·종료 시각·텍스트가 모두 보존된다** — 네 필드가 전부 출력 레코드에 실린다.
`diff -u fixture.canon fixture-extracted.canon` exit 0.

### 2.7 canonicalization이 허용하는 차이 — 폐쇄적 명시 여부

**문서 §7.3.1은 허용 차이를 5종으로 폐쇄 열거하고, 그 외는 전부 drift로 드러난다고 명시한다.**
5종을 각각 만들어 실행한 결과 **전부 문서대로 허용(동일 판정)** 됐다.

| 허용 차이 (문서 주장) | 실측 |
|---|---|
| UTF-8 BOM 유무 | **동일 (허용)** |
| CRLF ↔ LF | **동일 (허용)** |
| 줄 끝 trailing space·tab | **동일 (허용)** |
| 파일 앞뒤 빈 줄 개수 (EOF `0a` ↔ `0a 0a` 포함) | **동일 (허용)** |
| cue 사이 빈 줄 개수 | **동일 (허용)** |

### 2.8 음성 테스트 5건 — 전부 검출 (실측)

| 변경 | 기대 | 실측 |
|---|---|---|
| 시작 시각 `00:00:00,500` → `00:00:00,600` | 검출 | **검출** |
| 종료 시각 `00:00:05,500` → `00:00:05,400` | 검출 | **검출** |
| cue 텍스트 `[fixture cue 2]` → `[fixture cue X]` | 검출 | **검출** |
| cue 번호 `2` → `3` | 검출 | **검출** |
| cue 1건 삭제 | 검출 | **검출** |

**canonicalization이 timestamp나 텍스트 drift를 숨기지 않는다.**
따라서 raw-byte 동일성과 semantic 동일성을 뒤섞어 승인한 것이 아니다 — 문서 §7.3·§8은
두 비교를 **각각 요구**하고, §7.4.1은 raw 통과의 성립 조건을 명시한다. 이 구조는 정확하다.

### 2.10 F-01 — 남은 결함 (보통)

> **`docs/SEED_CORPUS_RESEARCH.md` §7.1.1, "생성 직후 확인" 블록 (파일 363행)**

```bash

| 위치 | 값 |
|---|---|
| §7.1.1 규약 표 (335행) | **98 bytes** |
| §7.4 (496행) | "**§7.1.1 규약(98 bytes, EOF `0a 0a`)에 대응**" |

- **M-01과의 관계:** 이 블록은 **M-01을 해소하기 위해 새로 추가된 구역** 안에 있다.
- **필요한 수정 조건:** `# 96` → `# 98`. 다른 변경은 필요하지 않다.

### 3.3 F-02 — 대화형 셸에서 가드가 후속 명령을 막지 못한다 (보통)

> **`docs/SEED_CORPUS_RESEARCH.md` §7.3 staging 블록, §7.5 staging 3행, §8 `ICLOUD-STAGING EXPORT` 행**

문서는 이 절차를 ` ```bash ` fenced block으로 제시하고 §7.1.1에서 "**복사 실행하면**"이라는
사용 방식을 전제한다. 그러나 `${VAR:?}`가 셸을 종료시키는지는 **실행 방식에 따라 다르다.**

**실행 방식별 실측 (미설정, 같은 블록·같은 환경):**

| 실행 방식 | exit | `mkdir` | `cp` | `/fixture-softsub.mkv` |
|---|---|---|---|---|
| `bash -c '<block>'` | 127 | 실행 안 됨 | 실행 안 됨 | **미생성** |
| `bash script.sh` | 1 | 실행 안 됨 | 실행 안 됨 | **미생성** |
| `sh script.sh` (dash) | **2** | 실행 안 됨 | 실행 안 됨 | **미생성** |
| `. ./script.sh` (source) | 1 | 실행 안 됨 | 실행 안 됨 | **미생성** |
| **대화형 `bash` (붙여넣기)** | **0** | `cannot create directory ''` | **실행됨** | **생성됨** |

**대화형 셸 실측 출력 (`script -q -c "bash -i"`로 tty 재현):**

```
bash: MCS_ICLOUD_STAGING_DIR: set MCS_ICLOUD_STAGING_DIR to the staging directory
mkdir: cannot create directory '': No such file or directory
2f2eb1ba73813133af5c311e3329c1bd5bf445f1192451397bb83af267a623ed  fixture-softsub.mkv
2f2eb1ba73813133af5c311e3329c1bd5bf445f1192451397bb83af267a623ed  /fixture-softsub.mkv
```

- **근거:** 대화형 bash에서 `${VAR:?}` 실패는 **셸을 종료시키지 않는다.** 오류를 출력한 뒤
  다음 명령이 그대로 실행되어 `cp -- fixture-softsub.mkv "/"`가 **성공했고,
  `/fixture-softsub.mkv`가 실제로 만들어졌다.** 이 파일은 검토 후 삭제했다.
- **영향:** **REVIEW-010 M-02가 막으려던 결과가 그대로 재현된다.** REVIEW-010 §2.3이 지적한
  것도 정확히 이 조건("`mkdir`은 실패하지만 스크립트가 중단되지 않는 구성")이었다. 가드는
  추가됐지만 **그 구성이 배제됐음을 문서가 보장하지 않는다.**
  §8의 acceptance 행은 "가드 통과(미설정·빈 값이면 **파일시스템 변경 없이 non-zero 종료**)"를
  기계적 확인 기준으로 규정하는데, 실행 방식을 고정하지 않으면 **이 기준이 성립하지 않는
  실행 경로가 존재한다.**
- **필요한 수정 조건 (택일 가능):**
  1. 이 블록의 실행 방식을 문서에 고정한다 — 예: 스크립트 파일로 저장해 `sh`/`bash`로 실행,
     또는 블록 선두에 `set -eu` 추가, 또는 전체를 `bash -c '…'` 단일 호출로 제시.
  2. 또는 가드를 실행 방식에 무관하게 만든다 — 예:
     `[ -n "${MCS_ICLOUD_STAGING_DIR:-}" ] || { echo "…" >&2; return 1 2>/dev/null || exit 1; }`
     형태로 후속 명령을 조건부로 묶거나, `&&` 연쇄로 연결한다.
  3. §8의 acceptance 행에 **어떤 실행 방식에서 성립하는 기준인지** 명시한다.

### 3.4 F-03 — 문서가 기록한 `exit 2`가 재현되지 않는다 (경미)

> **`docs/SEED_CORPUS_RESEARCH.md` §7.5, staging 가드 2행**

문서는 미설정·빈 문자열 두 케이스 모두 "**exit 2**"라고 기록한다.

| 문서 기대값 | 실측값 |
|---|---|
| exit **2** | `bash -c` → **127** / `bash script` → **1** / `sh`(dash) script → **2** / 대화형 → **0** |

- **근거:** `exit 2`는 **dash(`/bin/sh`)로 스크립트를 실행했을 때만** 나온다. 문서는 이 블록의
  셸을 지정하지 않으며(§7.3.1의 `srt-canon.sh`만 `#!/bin/sh`를 가진다), §7.2는 `export LC_ALL=C`를
  쓴다. 따라서 독자가 bash로 실행하면 문서의 값이 재현되지 않는다.
- **영향:** 재현 기록의 정확도 문제다. **안전성 결론(파일시스템 변경 없음)은 bash·dash 모두에서
  동일하므로 위험을 만들지는 않는다.** F-02와 달리 잘못된 동작을 유발하지 않는다.
- **필요한 수정 조건:** `exit 2`를 **non-zero**로 완화하거나, 값을 남기려면 **어떤 셸에서
  측정한 값인지** 함께 적는다 (F-02의 수정 1과 함께 처리하면 자연히 해소된다).

### 3.5 M-02 잔여 위험

  동작은 확인하지 않았다.** 문서도 그 범위를 요구하지 않는다.

## 10. 최종 판정

### **변경 요청**

**근거는 F-01·F-02·F-03 세 건이며, 모두 Source Owner가 현재 문서에서 수정할 수 있다.**

| ID | 심각도 | 위치 | 요지 |
|---|---|---|---|
| **F-01** | 보통 | `SEED_CORPUS_RESEARCH.md` §7.1.1 (363행) | 자체 검사 블록의 `# 96`이 같은 절의 규약(98 bytes)·§7.4·§7.5·실측과 모순. **규약을 지킨 파일을 위반으로 오판하게 한다** |
| **F-02** | 보통 | 같은 문서 §7.3 staging 블록 · §7.5 · §8 | 대화형 셸에서 `${VAR:?}` 가드가 후속 명령을 막지 못해 **`/fixture-softsub.mkv`가 실제로 생성됨**. M-02가 막으려던 결과가 재현된다. 실행 방식이 문서에 고정되지 않았다 |
| **F-03** | 경미 | 같은 문서 §7.5 staging 2행 | 기록된 `exit 2`가 dash에서만 재현되고 bash에서는 127/1. 셸을 지정하지 않았다 |

**왜 `승인`이 아닌가**

- F-01·F-02·F-03은 **재현 가능한 문서 결함**이다. 특히 F-02는 §8이 "기계적 확인"으로 규정한
  acceptance 기준이 성립하지 않는 실행 경로를 남긴다.
- 그와 **별개로** M-03·M-05의 1차 공식 원문을 직접 확인하지 못했으므로, F-01~F-03이 전부
  수정되더라도 이 환경에서는 `승인` 조건이 성립하지 않는다.

**왜 `차단`이 아닌가**

- 고정 SHA·tree·blob이 **하나도 이동하지 않았다.**
- M-01·M-02의 필수 실행 환경(동일 build FFmpeg)에 접근할 수 있었고, **판정을 실측으로
  확정했다.** 따라서 "승인 또는 변경 요청을 증거로 확정할 수 없는" 상태가 아니다.
- M-03·M-05의 접근 실패는 **개별 항목의 `차단` 판정**으로 기록했으며, 그 두 항목은
  `변경 요청`의 근거로 계산하지 않았다.
