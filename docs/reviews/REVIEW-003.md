### 3.1 M-06 잔여 반례 1 — `inserted_spans` 시간축이 바뀝니다

입력:

```text
정답 R = "a" (source [0,1))
TimeMapping: from=source, to=degraded
segments: source [0,1) -> degraded [0,1)
inserted_spans: degraded [1,2), kind="silence"
가설: "a" @ degraded [0,1), "x" @ degraded [1,2)
```

ARCHITECTURE §2.3은 `inserted_spans`를 `to_start/to_end`, 즉 degraded 시간축으로 정의합니다.
반면 EVALS 알고리즘 A는 A2에서 가설 시각을 source로 옮긴 뒤 A3에서 그 **source 시각**을
`inserted_span`과 비교합니다. 삽입 구간의 `x`는 source 시각이 존재하지 않습니다.

- 해석 1: degraded 시간축에서 먼저 `x`를 제외 → H=`"a"`, CER = 0/1 = **0.0**
- 해석 2: A2를 문자 그대로 수행하고 source 시각이 없는 `x`를 제외 대상으로 표시하지 못함 →
  H=`"ax"`, CER = 1/1 = **1.0**

제외 자체는 문자열 결합 전에 일어나지만, **어느 시간축에서 제외를 결정하는지**가 모순되어 값이 갈립니다.

### 3.2 M-06 잔여 반례 2 — `lines[]` 결합 구분자가 없습니다

입력:

```text
가설 cue = [0,4), lines=["A", "B"], 문자·단어 타이밍 없음
norm-v1은 A/B를 변경하지 않음
정답 무음 = [3.2,4)
```

알고리즘 C는 `lines[]`를 “하나로 이어붙인 뒤” 균등 배분한다고 하지만 구분자를 정하지 않습니다.

- 해석 1: 구분자 없이 `"AB"`, N=2 → B 중앙 3.0초 → 무음 귀속 문자 **0개**
- 해석 2: 공백으로 `"A B"`, N=3 → B 중앙 약 3.333초 → 무음 귀속 문자 **1개**

빈 cue와 정규화 후 grapheme cluster 수는 정의됐지만, 줄 경계 결합이 결정적이지 않습니다.
같은 문제는 `language_spans` 시간 투영에도 전파됩니다.
