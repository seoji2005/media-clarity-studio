# PRODUCT_SPEC.md — 제품 명세

무엇을 만들고, 무엇을 만들지 않는가.

마지막 갱신: 2026-08-09 (Phase 0)
상태: **초안 (Draft)** — 사람 제품 오너의 확정 전

---

## 1. 한 문장 정의

> 품질이 나쁜 다국어 영상에서 **읽을 만한 자막을 생성**하고,
> **시각적으로 손상된 영역을 그럴듯하게 재구성**하는 로컬 우선 도구.

---

## 2. 사용자와 상황

| 구분 | 사용자 | 상황 | 우선순위 |
|---|---|---|---|
| P0 | 과제 제출자 (본인) | 어려운 입력 영상에 대해 숨겨진 정답 자막에 가까운 결과를 내야 함 | Phase 1–2 |
| P1 | 개인 크리에이터 | 외국어 소스 영상에 자막을 붙이고 화질을 정리해 재활용 | Phase 3–4 |
| P2 | 소규모 제작 스튜디오 | 반복 작업의 배치 처리 | Phase 4 |

**공통 전제:** 사용자는 **자신의 PC에서** 처리하고 싶어 합니다.
미디어를 외부 서버에 올리는 것을 기본 동작으로 원하지 않습니다.

---

## 3. 입력의 성질 (설계를 규정하는 제약)

입력은 의도적으로 어렵습니다. 이 목록은 아키텍처와 평가 설계 전체의 근거입니다.

| 열화 유형 | 구체적 문제 | 영향을 받는 모듈 |
|---|---|---|
| 겹치는 발화 | 두 명 이상이 동시에 말함 → 텍스트 뒤섞임, 화자 귀속 실패 | `audio`, `asr`, `subtitle` |
| 크거나 불규칙한 잡음 | 비정상(non-stationary) 잡음 → 오인식, 단어 누락 | `audio`, `asr` |
| 긴 무음 | 무음에서 없는 문장을 만들어내는 환각(hallucination) | `audio`(VAD), `asr` |
| 다국어 전환 | 한 영상, 때로는 한 문장 안에서 언어가 바뀜 | `asr`, `subtitle` |
| 낮은 오디오 품질 | 대역 축소, 코덱 열화, 클리핑 | `audio`, `asr` |
| 낮은 영상 품질 | 압축 아티팩트, 저비트레이트 | `restore` |
| blur / mosaic 영역 | 정보가 **실제로 삭제됨** | `restore` |
| 의도적 저해상도 | 디테일 손실 | `restore` |

> **중요:** mosaic·blur는 정보가 **소실된** 것입니다. 되찾을 수 없습니다.
> 우리가 할 수 있는 것은 주변 문맥과 사전지식으로 **추정**하는 것뿐입니다 (`AGENTS.md` §1).

## 4. MVP 목표 (Phase 1 종료 시점)

**MVP는 자막입니다. 영상 재구성은 MVP가 아닙니다.**

| # | 목표 | 확인 방법 |
|---|---|---|
| G1 | 임의의 입력 영상에서 시간 정보가 붙은 자막 파일을 생성한다 | 파일이 생성되고 플레이어에서 재생됨 |
| G2 | 결과 품질을 **채점 원본 없이** 수치로 판단할 수 있다 | 합성 열화 세트 리포트 ([`EVALS.md`](EVALS.md)) |
| G3 | 무음 구간에서 없는 문장을 만들지 않는다 | 무음 환각률 지표 |
| G4 | 다국어 전환 구간에서 언어를 식별하고 해당 언어로 표기한다 | 언어 식별 정확도 |
| G5 | 겹치는 발화에서 완전히 무너지지 않는다 | 겹침 강도별 WER 곡선 |
| G6 | 자막이 사람이 읽을 수 있는 형식 규칙을 지킨다 | 포맷 검사 통과율 (CPS, 줄 길이, 줄 수) |
| G7 | 같은 입력 + 같은 설정 → 같은 결과 | 재현성 검사 |
| G8 | 실행 방법이 문서만 보고 재현 가능하다 | 사람 오너가 문서만으로 실행 성공 |

**MVP 성공 기준에 대한 정직한 한계**
"정답에 얼마나 가까운가"의 절대 수치 목표(예: WER 20% 이하)는 **지금 정하지 않습니다.**
기준선(baseline)을 측정하기 전에 정한 숫자는 근거가 없습니다.
Phase 1a에서 기준선을 잰 뒤 `docs/DECISIONS.md`에 목표치를 기록합니다. (미해결 **U-07**)

## 6. 사용자 흐름 (User Workflow)

### 6.1 Phase 1 (명령줄 기준)

```
1. 사용자가 입력 영상 파일을 지정한다
2. 도구가 미디어를 분석한다 (길이, 트랙, 해상도, 코덱)
3. 오디오를 추출·정규화한다
4. 발화 구간을 탐지한다 (무음 제외)
5. 각 구간의 언어를 식별한다
6. 음성을 텍스트로 전사한다
7. 텍스트를 자막 단위로 나누고 시간을 정렬한다
8. 자막 형식 규칙을 적용한다 (줄 길이, CPS, 줄 수)
9. 자막 파일을 저장한다
10. 처리 기록(manifest)을 함께 저장한다 — 어떤 설정으로 만들었는지
```

**사용자 개입 지점:** 3–9는 자동. 사용자는 **결과를 보고 수정**합니다.
자동 결과는 항상 **초안**이며 최종본이 아닙니다.

### 6.2 Phase 2 (영상 재구성 추가, 별도 실행)

```
1. 입력 영상 지정
2. 열화 영역 탐지 (blur / mosaic / 저해상도)
3. 영역별 재구성 시도
4. 시간적 일관성 검사
5. 인공물·환각 검사
6. 결과 저장 — "추정 결과"로 라벨링
7. 원본/추정 비교 자료 제공
```

**자막 흐름과 독립적으로 실행됩니다.** 하나가 실패해도 다른 하나는 진행됩니다.

### 6.3 Phase 3 (UI)

```
파일 끌어놓기 → 처리 옵션 선택 → 진행 상황 확인 → 결과 미리보기
→ 자막 직접 수정 → 원본/추정 비교 → 내보내기 → 프로젝트로 저장
```

## 7. 제품 경계 (Product Boundaries)

무엇이 이 제품 **안**이고 무엇이 **밖**인가.

| 안 (In) | 밖 (Out) |
|---|---|
| 로컬 미디어 파일 처리 | 스트리밍 서비스 연동 |
| 자막 생성·정렬·형식화 | 자막 번역 품질 보증 (U-08 확정 전) |
| 손상 영역 재구성 **추정** | 원본 복구 주장 (N1) |
| 재현 가능한 평가 리포트 | 채점 시스템 자동 제출 |
| 로컬 파일 정리·프로젝트 관리 | 협업·다중 사용자 편집 |
| 선택적 개인 클라우드 내보내기 (Phase 4) | 우리가 운영하는 서버에 미디어 저장 |
| 사용자 소유 미디어 | 저작권 침해 소지가 있는 사용 지원 |

## 8. 품질 속성 (Quality Attributes)

우선순위 순서입니다. 충돌하면 위가 이깁니다.

1. **정직성 (Honesty)** — 결과의 불확실성을 숨기지 않는다. 추정은 추정이라고 표시한다.
2. **재현성 (Reproducibility)** — 같은 입력·설정·시드 → 같은 출력. 평가의 전제.
3. **로컬 우선 (Local-first)** — 네트워크 없이 동작한다. 클라우드는 선택.
4. **안전한 기본값 (Safe defaults)** — 잘 모르는 사용자가 기본 설정으로 합리적 결과를 얻는다.
   파괴적 동작(원본 덮어쓰기 등)은 기본값이 아니다.
5. **모듈 독립성 (Modularity)** — 자막과 영상 재구성이 서로를 막지 않는다.
6. **관측 가능성 (Observability)** — 무엇을 왜 그렇게 했는지 기록이 남는다.
7. **성능 (Performance)** — 중요하지만 정확도·정직성보다 뒤. Phase 3에서 본격 대응.
