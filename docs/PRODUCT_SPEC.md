# PRODUCT_SPEC.md — 제품 명세

무엇을 만들고, 무엇을 만들지 않는가.

마지막 갱신: 2026-08-09 (Phase 0, REVIEW-001 반영)
상태: **초안 (Draft)** — 사람 제품 오너의 확정 전

---

## 1. 한 문장 정의

> 품질이 나쁜 다국어 영상에서 **읽을 만한 자막을 생성**하고,
> **시각적으로 손상된 영역을 그럴듯하게 재구성**하는 로컬 우선 도구.

---

## 2. 두 개의 범위를 구분한다 — 과제 vs 상용 제품

**이것이 이 문서에서 가장 중요한 구분입니다.** 이전 판은 둘을 섞어서,
과제에서 요구하는 산출물을 상용 제품의 우선순위 논리로 축소할 수 있게 적혀 있었습니다.

| | **A. 대학 과제 범위 (Assignment Scope)** | **B. 상용 제품 MVP (Commercial MVP)** |
|---|---|---|
| 성격 | **고정된 요구사항.** 우리가 줄일 수 없음 | 우리가 정하는 제품 결정 |
| 필수 산출물 | ① 숨겨진 정답에 가까운 **자막**<br>② 시각적으로 손상된 영역의 **자연스러운 재구성** | 자막 생성 + 평가 기반 (Phase 1) |
| 둘 중 하나를 뺄 수 있나 | **아니오.** 둘 다 요구됨 | 예. 제품 우선순위는 우리 재량 |
| 배점 비중 | **모름 (U-24).** 공개되지 않음 | 해당 없음 |
| 마감 | **있음 (U-11, 미확인)** | 없음 |

### 2.1 필수 규칙

| # | 규칙 |
|---|---|
| **AS-1** | 과제는 **자막과 시각 재구성을 모두** 요구한다. 시각 재구성은 선택 기능이 아니다 |
| **AS-2** | 배점 비중은 **알려져 있지 않다 (U-24).** "자막이 더 중요할 것"이라는 가정으로 시각 재구성을 폐기하지 않는다 |
| **AS-3** | 구현 **순서**를 자막 먼저로 두는 것은 허용된다. 그것은 순서이지 범위 축소가 아니다 |
| **AS-4** | 일정 압박으로 범위를 줄여야 한다면 **사람 오너가 결정한다.** 에이전트가 임의로 시각 재구성을 버리지 않는다 |

> **이전 판의 오류:** "자막이 채점 중심이므로 기한이 촉박하면 Phase 2를 포기하는 것이 옳다"라고
> 적혀 있었습니다. 이는 **검증되지 않은 배점 가정**에 기반한 범위 축소였습니다.
> 배점은 U-24로 미해결이며, 그것이 확인되기 전까지 두 산출물은 **동등하게 필수**입니다.

### 2.2 순서에 대한 제안 (범위가 아니라 순서)

자막을 먼저 착수하자는 제안의 근거는 "더 중요해서"가 아니라 **"측정 기준을 먼저 세우기 위해서"** 입니다.

- 자막은 정량 평가 체계를 세우기 쉽습니다 (텍스트 비교).
- 그 과정에서 만든 평가 하네스·`ReferenceBundle`·시간축 계약을 **시각 도메인이 그대로 재사용**합니다.
- 따라서 자막 먼저 = 시각 재구성의 **기반 공사**이기도 합니다.

이 순서 제안은 **제안됨(Proposed)** 상태입니다 (ADR-0004). 승인된 것이 아닙니다.

## 3. 사용자와 상황

| 구분 | 사용자 | 상황 | 우선순위 |
|---|---|---|---|
| P0 | 과제 제출자 (본인) | 어려운 입력 영상에서 **자막과 시각 재구성 결과 모두** 제출 | Phase 1–2 |

## 4. 입력의 성질 (설계를 규정하는 제약)

| 열화 유형 | 구체적 문제 | 영향을 받는 모듈 |
|---|---|---|
| 겹치는 발화 | 두 명 이상이 동시에 말함 → 텍스트 뒤섞임, 화자 귀속 실패 | `audio`, `asr`, `subtitle` |
| 크거나 불규칙한 잡음 | 비정상(non-stationary) 잡음 → 오인식, 단어 누락 | `audio`, `asr` |
| 긴 무음 | 무음에서 없는 문장을 만들어내는 환각(hallucination) | `audio`(VAD), `asr` |
| 다국어 전환 | 한 영상, 때로는 한 문장 안에서 언어가 바뀜 | `asr`, `subtitle` |
| 낮은 오디오 품질 | 대역 축소, 코덱 열화, 클리핑 | `audio`, `asr` |
| 낮은 영상 품질 | 압축 아티팩트, 저비트레이트 | `reconstruct` |
| blur / mosaic 영역 | 정보가 **실제로 삭제됨** | `reconstruct` |
| 의도적 저해상도 | 디테일 손실 | `reconstruct` |

> **중요:** mosaic·blur는 정보가 **소실된** 것입니다. 되찾을 수 없습니다.
> 우리가 할 수 있는 것은 주변 문맥과 사전지식으로 **추정**하는 것뿐입니다 (`AGENTS.md` §1).

## 5. 상용 MVP 목표 (Phase 1 종료 시점)

**이 절은 상용 제품 MVP(B 범위)에 대한 것입니다.** 과제 범위(A)는 §2를 따릅니다.

| # | 목표 | 확인 방법 |
|---|---|---|
| G1 | 임의의 입력 영상에서 시간 정보가 붙은 자막 파일을 생성한다 | 파일이 생성되고 플레이어에서 재생됨 |
| G2 | 결과 품질을 **채점 원본 없이** 수치로 판단할 수 있다 | 여러 신호의 평가 리포트 ([`EVALS.md`](EVALS.md) §1.1) |
| G3 | 무음 구간에서 없는 문장을 만들지 않는다 | 무음 환각률 + 무음 오탐률 (함께) |
| G4 | 다국어 전환 구간에서 언어를 식별하고 해당 언어로 표기한다 | 언어 식별 정확도, 전환점 F1 |
| G5 | 겹치는 발화에서 완전히 무너지지 않는다 | 겹침 강도별 cpWER 또는 완화 지표 곡선 |
| G6 | 자막이 사람이 읽을 수 있는 형식 규칙을 지킨다 | 형식 검사 통과율 |
| G7 | 같은 입력 + 같은 설정 → **선언된 재현성 등급 내에서** 같은 결과 | T1/T2/T3 등급별 검사 ([`ARCHITECTURE.md`](ARCHITECTURE.md) §6) |
| G8 | 실행 방법이 문서만 보고 재현 가능하다 | 사람 오너가 문서만으로 실행 성공 |

**정직한 한계**
"정답에 얼마나 가까운가"의 절대 수치 목표는 **지금 정하지 않습니다.**
기준선을 측정하기 전에 정한 숫자는 근거가 없습니다 (U-07).

### 6.3 N12의 근거 (수정됨)

**이전 판의 근거는 틀렸습니다.** "채점 피드백이 없어 학습 신호가 존재하지 않는다"라고 적었으나,
이는 사실이 아닙니다. 채점 피드백이 없어도 학습은 원리적으로 가능합니다
(우리가 만든 정답 데이터, 자기지도 학습, 공개 데이터셋 등).

**실제 근거는 자원과 범위의 문제입니다.**

| # | 근거 |
|---|---|
| 1 | **범위** — 이 프로젝트의 목표는 파이프라인 구축이지 모델 개발이 아니다 |
| 2 | **데이터** — 학습에 충분한 규모·라이선스의 데이터를 확보하지 못했다 (U-06) |
| 3 | **연산** — 로컬 GPU 자원이 학습에 충분한지 미확인 (U-23) |
| 4 | **일정** — 과제 마감이 미확인이며 (U-11), 학습은 일정 위험이 크다 |
| 5 | **평가 우선** — 학습을 하더라도 평가 체계가 먼저 있어야 개선을 확인할 수 있다 |

**따라서 N12는 "불가능"이 아니라 "현 자원과 일정에서 미루는 것"입니다.**
위 제약이 해소되면 재검토할 수 있습니다. 재검토 조건: U-06·U-11·U-23이 모두 해소되고,
평가 하네스가 동작하며, 기준선이 측정된 뒤.

## 7. 사용자 흐름 (User Workflow)

### 7.1 자막 흐름 (Phase 1, 명령줄 기준)

```
1. 입력 영상 파일 지정
2. 미디어 분석 (길이, 트랙, 해상도, 코덱, Timebase 확정)
3. 오디오 추출·정규화
4. 발화 구간 탐지 (무음 제외)
5. 구간별 언어 식별
6. 음성을 텍스트로 전사 (겹침이면 다중 스트림)
7. 자막 단위 분할 및 시간 정렬
8. 자막 형식 규칙 적용
9. 자막 파일 저장 + manifest 기록
```

**사용자 개입 지점:** 2–9는 자동. 사용자는 **결과를 보고 수정**합니다.
자동 결과는 항상 **초안**이며 최종본이 아닙니다. `needs_review`가 볼 곳을 알려줍니다.

### 7.2 시각 재구성 흐름 (Phase 2, 별도 실행)

```
1. 입력 영상 지정
2. 열화 영역 탐지 (blur / mosaic / 저해상도) — 이동 영역 포함
3. ★ ReconstructionPolicy 안전 게이트 판정
   → skip / 사용자 확인 요청 / 진행
4. 허용된 영역만 재구성 시도
5. 시간적 일관성 + 자명한 해 방어 검사
6. 인공물·환각 검사, 깨끗 영역 변경 검사
7. 결과 저장 — "추정 결과"로 라벨링
8. 원본/추정 비교 자료 제공
```

**3번은 건너뛸 수 없습니다.** 정책 없이 재구성을 호출하는 경로는 존재하지 않습니다.

**자막 흐름과 독립적으로 실행됩니다.** 산출물이 서로를 입력으로 쓰지 않습니다.

### 7.3 Phase 3 (UI)

```
파일 끌어놓기 → 처리 옵션 선택 → 진행 상황 확인 → 결과 미리보기
→ 자막 직접 수정 → 정책 확인 응답 → 원본/추정 비교 → 내보내기 → 프로젝트 저장
```

| 안 (In) | 밖 (Out) |

| 로컬 미디어 파일 처리 | 스트리밍 서비스 연동 |

## 9. 품질 속성 (Quality Attributes)

우선순위 순서입니다. 충돌하면 위가 이깁니다.

1. **안전성 (Safety)** — 재구성 안전 게이트를 우회하지 않는다. 확인 없이 진행하지 않는다.
2. **정직성 (Honesty)** — 결과의 불확실성을 숨기지 않는다. 추정은 추정이라고 표시한다.
   계산하지 못한 지표는 "미지원"이라고 적는다.
3. **재현성 (Reproducibility)** — **등급을 명시한 재현성.** manifest만으로 동일 출력을 주장하지 않는다.
4. **로컬 우선 (Local-first)** — 네트워크 없이 동작한다. 클라우드는 선택.
5. **안전한 기본값 (Safe defaults)** — 기본 설정으로 합리적 결과. 파괴적 동작은 기본값이 아니다.
6. **도메인 독립성 (Domain independence)** — 자막과 시각 산출물이 서로를 막지 않는다.
   단, 횡단 기반은 공유한다.
7. **관측 가능성 (Observability)** — 무엇을 왜 그렇게 했는지 기록이 남는다.
8. **성능 (Performance)** — 중요하지만 위 항목들보다 뒤. Phase 3에서 본격 대응.
